# 11. 펫 시스템

> 문서 상태: 초안 v0.1 · 작성일 2026-11-01
> 화면: [04 §9](04-screen-specifications.md#9-펫) · 데이터: [14 §4.9](14-data-model.md) · API: [15 §11](15-api-specifications.md)

## 1. 사용자 요구 [확정]

- ChatGPT 펫처럼 화면을 돌아다니는 캐릭터가 있으면 좋겠다.
- 프리셋이 이미 있고, 각자 커스터마이징한 펫을 추가할 수 있다.
- GIF로 해야 하나? 어차피 AI로 만들 거라 형식은 상관없다.
- 펫이 필요한 정보도 알려 주고, 챗봇도 펫과 대화하는 형태.
- 마우스 호버 시 애교, 클릭 시 깜짝 놀라기.
- 혼자 놀다가 마우스가 움직이면 슬금슬금 일어나서 쫄래쫄래 쫓아오기.
- 아무 움직임이 없으면 갸웃갸웃하며 멀뚱멀뚱 화면 너머 사용자를 보는 듯 쳐다보기.
- 치이카와 캐릭터들(특히 우사기)을 넣고 싶다 → **치이카와·우사기·하치와레는 사용자 지정 펫으로 내 계정에서만 쓴다.**
- 프리셋은 저작권 상관없는 캐릭터로: 동물 모티프 5개 — **판다, 곰, 병아리, 강아지, 백호**. AI가 귀여운 캐릭터를 생성해 만들어 주길 원함.
- 사용자 지정 펫 업로드 시 형식·방법의 자세한 설명이 있어야 하되, 화면에 다 노출하면 빽빽하므로 i 버튼 호버 정보 박스 같은 깔끔한 방식으로.

## 2. 역할과 원칙 [제안: ChatGPT 대화에서 제시, 사용자 이견 없음]

1. 펫은 장식이 아니라 **앱 전체를 돌아다니는 캐릭터이자 AI 비서의 얼굴**이다.
2. 귀여운 행동은 다양하게, 그러나 **실제 작업(일정 확인, 지출 입력)을 방해하지 않는다.**
3. **AI를 연결하지 않아도** 펫의 행동과 기본 알림은 작동한다.
4. **외형과 행동 시스템을 분리한다.** 새 캐릭터를 등록할 때마다 기능을 새로 개발하지 않는다. 우사기를 등록하면 기존 걷기·놀라기·따라오기·잠자기 행동에 우사기 전용 그림을 연결한다.
5. 캐릭터 행동은 기기 안의 **상태 머신**이 담당하고, AI는 대화·정보 분석만 맡는다(비용 낮고 반응 빠름).

## 3. 펫 종류

| 구분 | 기본 펫 | 사용자 지정 펫 |
|---|---|---|
| 캐릭터 | 판다, 곰, 병아리, 강아지, 백호 [확정] | 치이카와, 우사기, 하치와레 등 [확정] |
| 제공 | 앱 기본 제공 | 사용자가 직접 등록 |
| 공개 범위 | 모든 사용자 | **등록한 사용자만**(기본 비공개, 변경 불가 — 공유 기능 전까지) [확정] |
| 커스터마이징 | 이름, 움직임, 크기, 알림 (색상·액세서리 P2) | 이미지·애니메이션, 이름, 동작 연결, 움직임, 크기 |
| AI 비서 | 지원 | 동일하게 지원 |

### 3.1 기본 펫 5종 제작 지침 [제안]

- 권리: 앱이 제작한 독창 캐릭터. 기존 캐릭터와 닮지 않게(특히 치이카와 화풍 모방 금지 — 기본 펫은 공개 배포되므로).
- 공통 스타일(초안): 통통한 2.5등신, 큰 머리, 짧은 팔다리, 단순한 선, 파스텔 톤, 테마 하늘색(`primary`)과 어울리는 따뜻한 포인트 색 1개. 외곽선 2px 진한 갈회색(다크 모드에서도 보이게).
- 캐릭터별 포인트 [제안]:

| 펫 | 기본 이름(변경 가능) | 포인트 | 성격(말투) |
|---|---|---|---|
> **[확정 D-053] 사용자가 제공한 캐릭터 시트가 기준이다.** 아래 표의 이름·성격은 시트대로 바꾼다. 원래 이 표에 있던 초안 값은 시트로 대체됐다.
> 포몽(판다, 느긋하고 다정함, 대나무 잎) · 코몽(곰, 포근하고 든든함, 크림색 모자) · 삐요(병아리, 호기심 많고 활발, 머리 새싹) · 멍이(강아지, 애교 많고 꼬리를 흔듦, 갈색 귀) · 호야(백호, 호기심 많고 듬직, 장난기, 줄무늬·분홍 발바닥)
> 시트의 동작: 대기, 걷기, 앉기, 놀라기, 기뻐하기, 잠자기, 호버 반응(애교), 따라오기(D-055로 쓰지 않음), 무언가 발견. 소품 예시와 함께 있는 모습 예시가 있다.
> **[최신, V-07 완료] 고해상도 그림으로 교체**: 사용자가 시트를 참고해 만든 5종 × 8동작 1024px 투명 PNG(`assets/pets-hd/<id>/<동작>.png`)를 `scripts/fit-pets.mjs`로 256px에 맞춰 쓴다. 걷기도 정면 두 발 그림이라 아래 "그림 바꿔 끼우기 표"와 "따라오기" 그림은 없앴다. 그림을 다시 받으면 같은 폴더에 넣고 스크립트만 다시 실행.
> **현재 구현(0단계, 교체 전)**: 시트 원본(`assets/pets-reference.png`)에서 동작 그림을 잘라 쓴다(동작당 한 장, 96px, 움직임은 앱 효과). 시트 속 그림이 약 70px로 작아 크게 키우면 흐려진다. 더 선명하게 하려면 같은 AI 도구로 이 시트를 참고해 동작별 그림을 투명 배경 512px로 받아 `public/pets/<id>/<동작>.png`를 교체한다(코드 변경 불필요).
> 쉬는 동안 대기(60%)·앉기(30%)·무언가 발견(10%) 그림을 번갈아 쓴다. 끌 때는 놀라기, 호버는 호버 반응, 누르면 놀라기+깡충.
> **걷기(사용자 피드백 2026-11-01 "둥둥 떠다니는 느낌" 반영)**: ① 돌아다닐 때는 지금 높이에서 좌우로만 걷는다(위아래 이동은 사용자가 옮길 때와 모달 위에서 비켜 갈 때만). ② 걷기 그림을 몸통과 왼발·오른발(아래 14%를 좌우로 나눔)로 잘라 한 발씩 2.5px 들었다 내린다(초당 2.6걸음). ③ 발을 드는 동안만 앞으로 나아가고 디딜 때 멈춘다. 디딜 때 살짝 눌리고(3.5%), 걸음마다 몸이 좌우로 2.5° 기운다. 동작별 여러 장의 걷기 그림이 생기면 이 효과 대신 프레임 재생으로 바꾼다.
> **[최신] 두 발 아장아장(사용자 요청 "다 두 발로 아장아장, 네 발은 웃기다")**: 시트의 "걷기" 그림은 옆·네 발 모습이 많아 쓰지 않고, 정면으로 선 그림으로 걷는다(포몽·코몽·삐요·호야 = "따라오기" 그림, 멍이 = "애교" 그림). 한 발을 들면 디딘 발을 축으로 ±6° 뒤뚱, 발 3px 들기, 초당 2.8걸음. 정면 그림이라 방향을 뒤집지 않아 뒷걸음질이 생기지 않는다. 아래 "방향" 항목은 이 변경으로 대체됨.
> **펫별 그림 바꿔 끼우기 표(`ART`)**: 포몽 애교 → 기뻐하기(시트의 포몽 애교는 귀가 처져 강아지처럼 보임), 멍이 앉기·무언가 발견 → 대기(곰처럼 보임). 시트를 새로 받으면 이 표를 다시 검토한다.
> **방향(사용자 피드백 "뒤로 걷지 말고", 위 항목으로 대체됨)**: 시트의 걷기 그림 방향을 펫별로 기록한다 — 코몽·멍이는 왼쪽을 봄, 포몽·삐요·호야는 정면. 왼쪽을 보는 펫은 오른쪽으로 걸을 때 그림을 뒤집어 항상 가는 쪽을 본다. 정면 그림과 쉬는 그림은 뒤집지 않는다. 새 그림으로 바꾸면 이 표(`WALK_FACES`)도 갱신한다.
> **터치(사용자 피드백 "잡으면 겹쳐 보임")**: 애교(호버) 반응은 마우스에서만. 터치는 잡기 → 놀라기 → 놓으면 쉬기로 그림 전환을 최소화하고, 모든 동작 그림을 미리 디코딩해 둔다. 멍이 "앉기" 그림은 곰처럼 보여 쉬는 그림에서 제외(`SKIP_REST`) — 시트를 새로 받으면 다시 검토.

| 판다 | 판다 | 눈가 검은 무늬, 대나무 잎 소품 | 느긋함, 잘 졸음 |
| 곰 | 곰 | 갈색, 둥근 귀, 꿀단지 | 듬직, 차분 |
| 병아리 | 병아리 | 노란색, 작은 날개 파닥 | 호기심 많음, 통통 튐 |
| 강아지 | 강아지 | 처진 귀, 꼬리 흔들기 | 애교, 따라오기 좋아함 |
| 백호 | 백호 | 흰 바탕 회색 줄무늬, 분홍 리본(선택) | 씩씩, 장난기 |

- 제작 순서 [제안: ChatGPT 대화]: ① 캐릭터마다 **캐릭터 시트**(정면·측면·후면 + 주요 표정 6종: 기본, 웃음, 놀람, 졸림, 갸웃, 신남)를 먼저 확정 ② 시트를 기준으로 동작 프레임 제작. 이미지 생성만으로 모든 프레임의 형태를 일관되게 유지하기 어렵기 때문이다.
- **제작 방법: AI 이미지 생성 + 후처리** [확정 D-050]. 같은 캐릭터 설명문(프롬프트)을 고정하고, 결과를 정리(외곽선·색 통일)하는 후처리 단계를 둔다. 이미지 생성은 이 개발 환경 밖의 AI 이미지 도구(예: ChatGPT 이미지 생성)로 한다.

### 3.1.1 기본 펫 제작 절차 [제안] [검증 필요 V-07]

| 단계 | 작업 | 결과물 | 확인 기준 |
|---|---|---|---|
| 1 | 공통 스타일 프롬프트 고정 | 아래 템플릿 | 5종이 한 세트처럼 보임 |
| 2 | 캐릭터별 **캐릭터 시트** 생성: 정면·오른쪽 측면·뒷면 + 표정 6종(기본, 웃음, 놀람, 졸림, 갸웃, 신남) | 시트 이미지 1장/캐릭터 | 사용자가 마음에 드는 시트 확정 |
| 3 | 확정한 시트를 **참조 이미지로 넣고** 동작별 핵심 포즈 생성(동작당 2~4장: 시작·중간·끝) | 핵심 포즈 이미지 | 형태(귀·무늬·비율)가 시트와 같음 |
| 4 | 배경 제거 → 256×256 캔버스에 발 위치(앵커) 맞춰 배치 → 외곽선 두께·색 통일 | 정리된 프레임 PNG | §5.3 규격 |
| 5 | 핵심 포즈 사이 프레임 보강(필요한 동작만: 걷기·따라오기). 간단한 동작(숨쉬기·흔들림·점프)은 앱의 대체 효과로 처리해 프레임 수를 줄임 | 동작별 4~12프레임 | 8~12fps에서 끊김 없음 |
| 6 | 스프라이트 시트로 묶기 + pet.json 작성 | 펫 1종 묶음 | 업로드 검사(§5.4) 통과 |
| 7 | 앱에서 미리보기·밝은·어두운 모드 확인 | — | 사용자 검수 |

- 순서: 강아지 1종으로 1~7단계를 끝까지 해 본 뒤(V-07) 나머지 4종을 진행한다. 첫 1종에서 프레임 일관성이 부족하면 동작 수를 줄이고 대체 효과 비중을 늘린다.
- 최소 세트(1차 출시): 가만히 있기, 걷기, 놀라기, 잠자기, 애교 5개 동작만 그림으로, 나머지는 대체 효과. [제안]

### 3.2 사용자 지정 펫

- 여러 마리 등록 가능(계정당 최대 20마리 [제안]).
- 그날그날 원하는 펫으로 바꾼다("오늘의 펫"). [제안]
- 파일은 소유자만 접근 가능한 저장소에, 서명된 임시 주소로만 제공. 다른 사용자 화면·검색·공유에 나타나지 않는다.
- 권리 안내: 사용자 지정 펫 추가 화면 하단 작은 글 "직접 만들었거나 사용할 권리가 있는 이미지를 올려 주세요. 내 계정에서만 보여요." [제안] — 개인 사용이라도 권리 문제가 완전히 사라지는 것은 아니므로, 공개 공유 기능은 권리 확인·신고 기능 없이는 만들지 않는다. [확정: 공개 배포용과 개인용 분리]

### 4.4 이동 엔진 [제안]

- `requestAnimationFrame` 루프 1개. 펫 위치·속도·방향·상태를 기기 메모리에 보관(페이지 이동에도 유지 — 최상위 레이아웃에 상주).
- 활동 영역: PC 화면 하단 바닥선(아래 64px 띠) + 따라오기 시 화면 전체(단 안전 영역 제외). 모바일은 하단 탭 위 띠.
- 안전 영역 계산: `[data-pet-avoid]` 표시가 붙은 요소(모달, 팝오버, 빠른 추가 버튼, 토스트, 포커스된 입력)와 겹치지 않도록 매 0.5초 영역 목록 갱신(ResizeObserver·MutationObserver 기반, 매 프레임 측정 금지).
- 진행 방향에 따라 좌우 반전(측면 그림 하나로 양방향).
- 속도: walk 40px/s, follow 최대 160px/s(커서 거리 비례 가속, 도착 직전 감속).
- 위치 기억: 마지막 위치를 기기에 저장, 다음 실행 때 그 근처에서 등장.

## 7. 알림 연동 (규칙 기반, AI 불필요) [확정: 펫이 정보 알림] [제안: 규칙]

| 알림 원천 | 펫 표현 | 우선순위 |
|---|---|---|
| 일정 임박(설정 시점) | notify + "30분 뒤 주간 계획 정리" | 높음 |
| 결제 예정(당일·1일 전) | notify + "내일 넷플릭스 13,500원" | 중간 |
| 해지 예정 | notify | 중간 |
| 목표 체크 누락 | 말풍선만(손짓 없음) | 낮음 |
| 예산 주의·초과 | notify | 중간 |
| 목표 달성 | celebrate | 즉시 |
| 카드 실적 | 말풍선 | 낮음 |

- 빈도 제한: 같은 종류 하루 1회(일정 제외), 전체 시간당 최대 3회. 방해 금지 시간에는 말풍선 없음.
- 말풍선은 4초 표시 후 접혀 펫 머리 위 작은 점(읽지 않음 표시)으로 남는다. 탭하면 다시 펼침 → 관련 화면으로.
- 같은 알림이 알림 센터에도 남는다(펫을 숨겨도 정보를 잃지 않음).

## 8. AI 대화 연동

- 펫 클릭 → 미니 대화창. 대화 상대 이름·아바타 = 오늘의 펫. [확정]
- 펫별 말투(성격)는 시스템 프롬프트의 짧은 지시로 반영(예: 강아지 "애교 있는 반말 섞인 존댓말"). 사용자 지정 펫은 성격 입력란(선택, 100자). [제안] P2
- AI 미연결: 펫 클릭 시 대화창에 연결 안내 + 오늘의 요약(규칙 기반: 오늘 일정 수, 결제 예정, 남은 예산) 카드. AI 없이도 펫이 "도와주는" 느낌을 유지. [제안]
- AI 데이터 접근 권한 확인은 대화 요청 전에 서버에서 수행. [12 §6]

## 10. 성능·접근성

- 프레임 루프 1개, DOM 요소 1개(`img` 또는 `canvas`)에 스프라이트 위치만 변경(transform, 리플로우 없음).
- 에셋 지연 로딩: idle 먼저, 나머지 동작은 대기 중 미리 불러오기.
- 펫 레이어 전체 `aria-hidden`, 키보드 포커스 받지 않음. 펫 메뉴 기능(대화, 숨기기)은 상단바 프로필 메뉴에도 있다(키보드 사용자 경로).
- 목표: 프레임당 메인 스레드 2ms 이하. [01 NFR-PERF-003]

## 15. 업로드 가이드 초안 (화면 문구)

> 가이드는 [04 §9.5](04-screen-specifications.md#95-펫-만들기-가이드-scr-help-pet-제안-chatgpt-제안-구성)의 목차를 따른다. 아래는 각 장의 핵심 문구 초안이다.

**1. 시작하기**
- 기본형: 그림 한 장으로 펫을 만들어요. 걷기·놀라기 같은 움직임은 앱이 자연스럽게 만들어 줘요.
- 애니메이션형: 동작마다 움직이는 그림을 넣어요. '가만히 있기'만 있으면 시작할 수 있고, 나머지는 천천히 추가해도 돼요.

**2. 파일 형식**
- 한 장: PNG, WebP. 움직이는 그림: GIF, APNG, 움직이는 WebP. 여러 동작 한 번에: ZIP.
- 정사각형(256×256px 권장), 배경은 투명하게, 파일 하나에 2MB 이하.

**3. 동작 목록**
- 표: 동작 이름 · 언제 나오나요 · 없으면 어떻게 되나요 (§5.1을 사용자 말로).

**4. 움직이는 그림 만들기**
- 캐릭터의 발 위치를 모든 동작에서 같게 맞춰 주세요. 그래야 동작이 바뀔 때 펫이 튀지 않아요.
- 오른쪽을 보는 모습으로 그려 주세요. 왼쪽은 앱이 뒤집어 보여 줘요.
- 1초에 8~12장 정도가 자연스러워요.

**5. 동작 묶음(ZIP)**
- 폴더 구조와 pet.json 예시(§5.4), 샘플 내려받기.

**6. 문제 해결**
- 네모난 배경이 보여요 → 배경을 투명하게 저장해 주세요.
- 펫이 동작마다 위아래로 튀어요 → 발 위치를 맞춰 주세요.
- 파일이 너무 커요 → 크기를 256px로 줄이거나 [자동으로 줄이기]를 눌러 주세요.
- 일부 동작이 안 보여요 → 동작 이름(파일 이름)이 목록과 같은지 확인해 주세요.
