# 10. 건강 기록

> 문서 상태: 초안 v0.1 · 작성일 2026-11-01
> 화면: [04 §7.9~7.10](04-screen-specifications.md#79-건강-scr-hlt-01-확정-생리주기-체중-혈당-날짜별-기록) · 데이터: [14 §4.8](14-data-model.md) · API: [15 §10](15-api-specifications.md)

## 1. 사용자 요구 [확정]

- 건강 상태 관리.
- 생리주기 관리.
- 그 김에 혈당이나 몸무게 같은 것을 날짜별로 기록.

## 2. 원칙 [제안]

1. **기록 도구이지 의료 판단 도구가 아니다.** "정상/비정상", "위험" 같은 판정 문구를 쓰지 않는다. 사용자가 정한 목표 범위만 표시한다.
2. **민감 정보는 기본으로 숨긴다.** 홈 위젯·캘린더 오버레이·검색·AI 접근 모두 기본 꺼짐.
3. **입력은 빠르게.** 체중은 숫자 하나, 생리 시작은 탭 한 번.

## 3. 생리주기 — 만들지 않음(D-063)

> 사용자 결정으로 범위에서 뺐어요. 아래는 기록용으로만 남겨 둠.

### 3.1 기록

| 필드 | 필수 | 비고 |
|---|---|---|
| 시작일 | 필수 | `오늘 시작` 버튼 또는 날짜 선택 |
| 종료일 | 선택 | `오늘 끝남` 버튼. 비워 두면 "진행 중" |
| 양 | 선택 | 날짜별: 적음/보통/많음 |
| 증상 | 선택 | 칩: 복통, 두통, 피로, 기분 변화, 여드름 + 직접 추가 |
| 메모 | 선택 | |

### 3.2 예측 [제안]

```
주기 길이(i) = 시작일(i+1) − 시작일(i)
평균 주기    = 최근 최대 6개 주기 길이의 평균 (이상치 제외: 15일 미만·60일 초과)
평균 기간    = 최근 최대 6개 (종료일 − 시작일 + 1)의 평균
다음 예정일  = 마지막 시작일 + 평균 주기
```

- 주기 기록 2개 미만이면 예측하지 않는다. "주기를 두 번 이상 기록하면 예정일을 알려 드려요".
- 예정일을 지나도 시작 기록이 없으면 "예정일이 3일 지났어요" 정도만(판단 문구 없음).
- 배란일·가임기 예측은 하지 않는다(의료적 정확성·민감성). 요구 시 재검토 [18 Q-100].
- ⓘ: "최근 6번 주기의 평균으로 계산해요. 실제와 다를 수 있어요."

### 3.3 표시

- 건강 요약 카드: 다음 예정일, 남은 날, 진행 중이면 "3일째".
- 주기 달력: 월 격자에 기록일(진한 `--health`), 예측 구간(옅은 점선).
- 주기 길이 추이 막대 그래프.

## 4. 체중

| 필드 | 규칙 |
|---|---|
| 날짜·시간 | 기본 지금 |
| 값 | kg, 20.0~300.0, 소수 1자리 |
| 메모 | 선택 |

- 하루 여러 번 허용. 일별 대표값 = 그날 마지막 값(설정: 첫 값/평균 [제안] P2).
- 추세: 선 그래프 + 7일 이동평균 선(옅게). 목표 체중(선택) 가로선.
- 다이어트 목표(목표 영역)와 연결: 수치 목표 자동 연결 옵션에 "체중(최근 값)" 추가 [제안] P2.

## 5. 혈당

| 필드 | 규칙 |
|---|---|
| 날짜·시간 | 기본 지금 |
| 측정 시점 | 공복 / 식전 / 식후 1시간 / 식후 2시간 / 취침 전 / 기타 |
| 값 | mg/dL, 20~600 정수 |
| 메모 | 선택(먹은 것 등) |

- 목표 범위: 측정 시점별로 사용자가 입력(기본값 없음 — 의학적 기준을 앱이 제시하지 않음 [제안]). 입력하면 그래프에 띠로 표시.
- 단위 mmol/L 지원 여부 [미결정 Q-101] (추천: 1단계는 mg/dL만).

## 6. 사용자 정의 지표 [제안] P2

- 이름, 단위, 값 형식(숫자/예·아니오/1~5 척도), 하루 여러 번 여부.
- 예: 수면 시간, 혈압(수축기·이완기 두 값 — 복합 지표는 별도 유형), 물 마신 컵 수.
- 매일 하는 습관(물 마시기)은 트래커가 더 맞다는 안내를 지표 추가 화면 ⓘ에.

## 7. 개인정보 보호 [제안]

| 보호 장치 | 기본값 | 설명 |
|---|---|---|
| 홈 건강 위젯 | 끔 | 켤 때 주의 문구 |
| 캘린더 생리 예정일 오버레이 | 끔 | |
| 검색 결과 포함 | 끔 | |
| AI 데이터 접근 | 끔 | 켜도 대화마다 "건강 기록을 참고했어요" 근거 표시 + 감사 로그 |
| 건강 기록 잠금 | 끔 | 켜면 건강 탭 진입 시 잠금 해제 필요, 5분 무동작 또는 앱 이탈 시 다시 잠김. 방식: 패스키(기기 생체 인증) 또는 앱 PIN [미결정 Q-042] |
| 알림 문구 | 모호하게 | 잠금 화면에 보이는 푸시는 "건강 기록 알림이 있어요"처럼 내용 없이 [제안] |
| 저장 | 필드 단위 추가 암호화 | 값·메모를 애플리케이션 키로 암호화 저장 [미결정 Q-041: 검색·집계 성능과 맞교환] |
| 내보내기 | 기본 제외 | 내보내기 화면에서 체크해야 포함 |
| 완전 삭제 | 영역 단위 가능 | 설정 > 개인정보 > `건강 기록 모두 영구 삭제`(Alert Dialog + 재인증) — soft delete 예외 [확정 원칙: 개인정보 완전 삭제] |

- 다중 사용자·공개 단계: 건강 정보는 법령상 민감정보 처리 대상이 될 수 있어 별도 동의가 필요하다 [검증 필요: 개인정보보호법 검토] [18 Q-102].

## 8. 예외

| 상황 | 처리 |
|---|---|
| 생리 시작을 두 번 연속 기록(종료 없이) | "이전 주기가 아직 진행 중이에요. 이전 주기를 끝내고 새로 시작할까요?" |
| 값 범위 밖 | 필드 아래 "20~300 사이로 입력해 주세요" |
| 잠금 해제 실패 5회 | 30초 대기, 계정 비밀번호로 해제 가능 |
| 잠금 방식 기기 변경 | 패스키는 기기·계정 동기화 따라감, 없으면 계정 비밀번호로 해제 후 다시 등록 |
