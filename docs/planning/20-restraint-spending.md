# 20. 참은 소비

> 문서 상태: 초안 v0.1 · 작성일 2026-11-01
> 관련: [06 돈 관리](06-finance.md) · [09 위시리스트](09-wishlist.md) · 화면 [04 §6.14](04-screen-specifications.md#614-참은-소비-scr-fin-14) · 데이터 [14 §4.4](14-data-model.md) · API [15 §6](15-api-specifications.md)

## 1. 사용자 요구 [확정]

- **참은 소비 목록**: 진짜 사고 싶었는데 참은 것들을 기록한다.
- '사치' 분류에 들어간 지출과, 분류별 예산 초과 금액을 **합산한 만큼** 참은 소비 목록을 채워야 한다.
  - 뜻: 사치를 했거나 돈을 많이 썼으니, 그만큼 무언가를 참아야 한다.
- 위시리스트의 Want(갖고 싶음)나 Like(관심)에 있었는데 **한 달 내내 구매하지 않은 물건**을 이 목록에 넣는다.
- 그러므로 위시리스트 물건에는 **가격**이 있어야 하고, 구매한 뒤 **구매했다고 체크**할 수 있어야 한다. → [09](09-wishlist.md)
- 영화·드라마·도서 위시는 **시청 완료·완독 처리하고 후기를 남기는 곳(작품 기록)으로 넘어갈 수** 있어야 한다. → [09 §7](09-wishlist.md), [08](08-journal-and-media.md)

## 2. 용어 (화면 문구)

| 화면 문구 | 뜻 | 내부 |
|---|---|---|
| 참은 소비 | 메뉴·목록 이름 | `restraint` |
| 참아야 할 금액 | 이번 달 채워야 하는 목표 금액 | `target` |
| 참은 금액 | 목록에 기록된 금액 합계 | `filled` |
| 더 참아야 해요 | 참아야 할 금액 − 참은 금액 (양수일 때) | `shortfall` |
| 사치 | 참아야 할 금액에 그대로 더해지는 지출 분류 | `fin_categories.counts_toward_restraint = true` |
| 지난달에서 넘어온 금액 | 지난달 부족분 | `carried_in` |

## 3. 참아야 할 금액 계산 [확정: 사치 + 예산 초과 합산] [제안: 세부 규칙]

```
이번 달 참아야 할 금액
  = 사치 분류 지출 합계(환불 차감)
  + Σ 분류별 예산 초과액   (예산을 정한 분류만, 사치 분류는 제외)
  + 지난달에서 넘어온 금액  (§6, 설정에 따라)
  + 나중에 산 물건 금액     (§5.3)

분류 c의 예산 초과액 = max(0, 분류 c 사용액 − 분류 c 예산)
```

| 규칙 | 내용 | 이유 |
|---|---|---|
| 사치 분류는 초과액 계산에서 뺀다 | 사치 지출은 이미 전액이 더해졌으므로, 사치 분류에 예산을 정했더라도 초과액을 또 더하지 않는다 | 이중 계산 방지 |
| 예산이 없는 분류 | 초과액 0 | 기준이 없음 |
| 분류 사용액 | [06 §4.1](06-finance.md)과 같은 정의(큰 지출·고정 지출에 연결된 지출 제외) | 예산 화면과 숫자가 같아야 함 |
| 큰 지출 계획 초과 | 포함하지 않음 [확정 D-042] | 큰 지출은 미리 계획한 돈. 사용자 요구는 "영역별 예산 초과" |
| 예정(미래 날짜) 지출 | 포함하지 않음 | 쓴 돈 기준 |
| 사치로 정할 분류 | 기본 `사치` 1개. 분류 설정에서 다른 분류도 `참은 소비에 포함`을 켤 수 있음 [제안] | 사용자마다 사치의 범위가 다름 |
| 계산 시점 | 이번 달은 지출이 생길 때마다 실시간 갱신. 지난 달은 월 정산(§6) 때 고정 | |

- 기본 지출 분류에 **사치**를 추가한다. [확정: '사치' 카테고리] → [04 §6.13 기본 분류](04-screen-specifications.md#613-분류결제수단-관리-scr-fin-13)
- 사치 분류 ⓘ 문구: "이 분류에 쓴 돈만큼 참은 소비 목록을 채워야 해요."

## 4. 참은 소비 목록 채우기

### 4.1 채우는 세 가지 방법

| 방법 | 언제 | 금액 | 근거 |
|---|---|---|---|
| **위시에서 자동으로** | 월 정산 때(다음 달 1일) | 위시 가격 | [확정] 한 달 내내 안 산 갖고 싶음·관심 물건 |
| **직접 기록** | 언제든 | 사용자가 입력 | [확정] "진짜 사고 싶었는데 참은 것" 기록 |
| **위시를 그만둘 때** | 위시 `그만둠` 처리 시 "참은 소비로 기록할까요?" | 위시 가격 | [제안] 사기로 했다가 마음을 접은 것도 참은 것 |

### 4.2 위시 자동 포함 조건 [확정: Want·Like, 한 달 내내 미구매] [제안: 판정 세부]

월 M을 정산할 때, 아래를 **모두** 만족하는 쇼핑 위시는 월 M의 참은 소비로 자동 기록된다.

1. 구분이 월 M 마지막 날 기준 `갖고 싶음` 또는 `관심`이다. (`필요`는 제외 — 필요해서 사야 하는 물건은 참을 대상이 아님)
2. 월 M **1일 전부터** 위시에 있었다. (월 중간에 담은 물건은 "한 달 내내"가 아니므로 다음 달부터 대상)
3. 월 M 동안 `구매함`이나 `그만둠`이 되지 않았고 지금도 `담아둠` 상태다.
4. **가격이 있다.** 가격이 없으면 포함하지 않고 정산 화면에 "가격이 없어 넣지 못한 위시 2개" `[가격 넣기]`로 안내한다.
5. 이전 달에 이미 참은 소비로 기록된 적이 없다. **한 물건은 한 번만 센다** [확정 D-039]. 자동 포함, 그만둠, 직접 기록의 위시에서 고르기 중 어느 경로로 기록됐든 같다. 기록이 `이번 달에서 빼기`로 제외된 경우만 다시 대상이 된다.

- 자동 기록된 항목은 정산 화면에서 하나씩 뺄 수 있다(`이번 달에서 빼기`). 사용자가 직접 확인하지 않아도 기본은 포함이다. [확정: "넣어야 해"]
- 위시 물건은 참은 소비로 기록된 뒤에도 **위시에 그대로 남는다**(여전히 갖고 싶을 수 있음). 위시 카드에 작은 표시 "10월에 참음".

### 4.3 직접 기록 필드

| 필드 | 필수 | 비고 |
|---|---|---|
| 이름 | 필수 | 예: "한정판 운동화" |
| 금액 | 필수 | 사려고 했던 가격 |
| 날짜 | 필수 | 기본 오늘. 이 날짜가 속한 달에 더해짐 |
| 참은 이유·메모 | 선택 | 예: "세일이라 흔들렸지만 이미 비슷한 게 있음" |
| 이미지·링크 | 선택 | |
| 위시에서 고르기 | 선택 | 위시 목록에서 골라 이름·가격·이미지를 채움. 이렇게 고른 위시는 자동 포함 대상에서 빠짐(이중 계산 방지) |

### 4.4 채움 상태

| 상태 | 조건 | 표시 |
|---|---|---|
| 참을 것 없음 | 참아야 할 금액 0 | "이번 달은 참아야 할 금액이 없어요" |
| 진행 중 | 참은 금액 < 참아야 할 금액 | 막대 + "32,000원 더 참아야 해요" |
| 달성 | 참은 금액 ≥ 참아야 할 금액 | 막대 가득 + "이번 달 목표만큼 참았어요" (넘친 금액은 다음 달로 넘기지 않음 [제안]) |

- 이번 달 진행 중에는 아직 월 정산 전이라 위시 자동 포함분이 없다. 대신 **"이번 달 말에 들어갈 후보"**(조건 1·2·4를 이미 만족하고 아직 안 산 위시)와 그 합계를 미리 보여 준다. "지금 이대로 사지 않으면 98,000원이 채워져요."

## 5. 다른 기능과의 연결

### 5.1 지출 입력
- 사치 분류로 지출을 저장하면 토스트: "사치 지출을 기록했어요 · 이번 달 참아야 할 금액 +50,000원".
- 분류 예산을 넘기는 지출이면: "식비 예산을 12,000원 넘었어요 · 그만큼 참아야 할 금액에 더해져요".

### 5.2 위시 구매
- 자동 포함 후보인 위시를 `구매함`으로 바꾸면 후보에서 빠진다(아무 일 없음).

### 5.3 참았다고 기록한 물건을 나중에 산 경우 [확정 D-041]
- 이미 참은 소비로 기록된 위시를 나중에 `구매함`으로 바꾸면:
  - 원래 기록은 지우지 않고 "나중에 샀어요"로 표시한다(이력 보존).
  - 그 금액을 **구매한 달의 참아야 할 금액에 더한다.** 참았다고 했던 것을 결국 샀으니 그만큼 다시 참아야 한다.
  - 구매 처리 화면에 안내: "10월에 참은 물건이에요. 사면 이번 달 참아야 할 금액에 159,000원이 더해져요."
- 채택하지 않은 대안: 원래 달의 참은 금액에서 빼기(지난 달 정산을 다시 열어야 해서 복잡).
- 구매를 되돌리면(구매함 취소) 더했던 금액도 함께 빠진다.

## 6. 월 정산 [제안]

- 매달 1일 00:30(사용자 시간대)에 지난달을 정산한다. 본인 PC가 꺼져 있었다면 켜질 때 따라잡기로 실행한다. [16 §5.5]
- 정산 내용:
  1. 지난달 참아야 할 금액 확정(사치 합계, 분류별 초과액, 넘어온 금액, 나중에 산 물건).
  2. 위시 자동 포함 조건(§4.2)으로 항목 생성.
  3. 참은 금액 합계, 부족분 계산.
  4. **부족분 넘기기** [확정 D-040]: 부족분을 이번 달 "지난달에서 넘어온 금액"으로 더한다. 설정 `부족한 금액을 다음 달로 넘기기`(기본 켬)로 끌 수 있다. 넘어온 금액도 다시 못 채우면 그다음 달로 계속 쌓인다.
  5. 정산 결과를 저장(이후 지출을 고쳐도 지난 정산은 자동으로 바뀌지 않음. `다시 정산`으로 갱신 가능).
- 알림·펫: "10월 정산이 끝났어요. 참아야 할 금액 182,000원 중 210,000원을 참았어요" 또는 "32,000원이 부족해서 11월로 넘어가요". 정산 결과 화면으로 이동.
- 정산 후 7일 동안은 지난달 자동 포함 항목을 빼거나 직접 기록을 추가할 수 있다. 그 뒤에도 수정은 가능하되 `다시 정산`이 필요하다. [제안]

## 7. 예시

```
10월
  사치 분류 지출            가방 89,000 + 향수 50,000          = 139,000
  분류별 예산 초과          식비 18,000 + 쇼핑 25,000           =  43,000
  지난달에서 넘어온 금액                                      =       0
  ─────────────────────────────────────────────────────
  참아야 할 금액                                               182,000

  참은 소비
   - 직접 기록 · 10/12 한정판 운동화                            129,000
   - 위시 자동 · 무선 이어폰(갖고 싶음, 9월부터 담아둠)            89,000
  ─────────────────────────────────────────────────────
  참은 금액                                                   218,000  → 달성
```

## 9. 예외 상황

| 상황 | 처리 |
|---|---|
| 사치 분류 지출을 다른 분류로 고침 | 이번 달이면 즉시 재계산. 지난 달이면 정산 화면에 "정산 뒤에 바뀐 지출이 있어요" `[다시 정산]` |
| 지출 삭제·환불 | 같음 |
| 위시 가격을 정산 뒤에 바꿈 | 이미 기록된 금액은 기록 시점 값 유지 |
| 위시 삭제 | 이미 기록된 참은 소비는 남음(이름·금액 복사본 보관) |
| 사치 분류를 삭제 | 다른 분류로 옮기기 Dialog에서 "참은 소비에 포함" 여부도 함께 옮김 |
| 예산을 정산 뒤에 바꿈 | 지난 달은 `다시 정산` 전까지 그대로 |
| 참아야 할 금액이 매우 큼(예산을 크게 넘김) | 그대로 표시. 판단 문구 없이 숫자만 [제안] |

|---|---|

| 월 정산(위시 자동 포함, 부족분 넘기기), 이번 달 후보 미리 보기, 정산 알림 | P0 |
