# 04. 화면 명세

> 문서 상태: 초안 v0.1 · 작성일 2026-11-01
> 전제: [02 정보 구조](02-information-architecture.md)의 화면 계층·주소, [03 디자인 시스템](03-design-system.md)의 토큰·컴포넌트 규칙.
> 표식 규칙은 [00 §0](00-overview.md#0-이-문서-묶음을-읽는-법). 이 문서의 화면 구성은 별도 표시가 없으면 **[제안]** 이다. 사용자 요구에서 직접 온 항목은 **[확정]** 으로 표시한다.

## 0. 명세 읽는 법

각 화면은 다음 순서로 적는다.

1. **목적·진입** — 사용자가 이 화면에서 하려는 일, 들어오는 경로
2. **정보 우선순위** — [02 §7](02-information-architecture.md#7-화면별-정보-우선순위-요약)의 A~E 등급
3. **레이아웃** — PC / 모바일 (필요 시 태블릿 차이)
4. **구성 요소** — 요소 · shadcn 컴포넌트 · 선정 이유
5. **인터랙션** — 클릭·탭·키보드·제스처
6. **상태** — 로딩 · 빈 화면 · 오류 · 오프라인 · 특수 상태
7. **수정·삭제·데이터 연결**
8. **화면 문구** — 실제 노출 문구(일부). 따옴표 안이 화면 문구다.

와이어프레임의 기호: `[버튼]` 버튼, `( )` 선택지, `▾` 펼침, `ⓘ` i 설명, `?` 사용법, `···` 추가 작업, `▢` 이미지·썸네일, `━━` 진행 막대.

## 1. 공통 요소

### 1.1 앱 셸 (SCR-SHELL)

**목적**: 모든 화면을 감싸는 틀. 내비게이션, 전역 오버레이(빠른 추가·검색·알림·펫·AI)를 담는다.

**레이아웃**

| 폭 | 구성 |
|---|---|
| 모바일 | 상단바(56px, 스크롤 시 그림자) + 콘텐츠 + 하단 탭(64px + 안전 영역) + 빠른 추가 버튼 |
| 태블릿 | 접힌 사이드바(56px) + 상단바 + 콘텐츠 |
| PC | 사이드바(240px, 접기 가능) + 상단바(56px) + 콘텐츠(최대 1200px, 가운데) |

**구성 요소**

| 요소 | 컴포넌트 | 선정 이유 |
|---|---|---|
| PC 메뉴 | `Sidebar` (collapsible="icon") | 접기·아이콘 모드·키보드 단축(⌘B)·상태 쿠키 저장이 내장 |
| PC 하위 메뉴 | `Sidebar` 메뉴 + `Collapsible` | 현재 영역만 펼쳐 메뉴 길이를 짧게 유지 |
| 모바일 하단 탭 | 커스텀(`nav` + 링크 5개) | shadcn에 하단 탭이 없음. 아이콘 24px + 라벨 11px |
| 상단바 위치 표시(PC) | `Breadcrumb` | 깊은 화면(카드 상세 등)에서 위치·되돌아가기 |
| 검색 진입 | PC: 입력창 모양 `Button`(+`Kbd` ⌘K) / 모바일: 아이콘 버튼 | PC는 단축키를 학습시키고, 모바일은 공간 절약 |
| 빠른 추가 | PC: `Button` "추가" + `DropdownMenu` / 모바일: 고정 원형 버튼 + `Drawer` | §1.2 |
| 알림 | 아이콘 버튼 + `Badge`(숫자) → PC `Popover` / 모바일 전체 화면 | §1.4 |
| 프로필 | `Avatar` + `DropdownMenu` (설정, 펫 관리, 테마, 로그아웃) | 자주 쓰지 않는 메뉴를 한곳에 |
| 토스트 | `Sonner` (모바일: 하단 탭 위, PC: 오른쪽 아래) | 흐름을 끊지 않는 결과 알림 |
| 오프라인 띠 | 커스텀 띠(상단바 아래 28px) | 모든 화면 공통 상태 |

**인터랙션**
- PC 사이드바 접기: 상단 버튼 또는 `⌘/Ctrl+B`. 접힘 상태에서 메뉴 아이콘 호버 시 `Tooltip`으로 이름.
- 모바일 하단 탭을 다시 누르면 해당 영역의 첫 화면으로 돌아가며 맨 위로 스크롤.
- 모바일에서 아래로 스크롤하면 상단바는 유지, 빠른 추가 버튼은 작아지지 않음(항상 같은 위치가 학습에 유리).
- 화면 전환 시 펫 레이어는 유지된다(언마운트 금지). → [11](11-pet-system.md)

**상태**
- 첫 실행(캐시 없음): 셸 즉시 표시 + 콘텐츠 Skeleton.
- 세션 만료: 현재 화면 위에 Dialog "다시 로그인해 주세요" `[로그인]` — 작성 중인 입력은 기기에 임시 보관 후 로그인 뒤 복원.
- 새 버전 배포 감지: 토스트 "새 버전이 있어요" `[새로고침]` (자동 새로고침 금지: 입력 중 손실 방지).

### 1.2 빠른 추가 (SCR-QA) [확정: 자주 하는 행동은 최소 조작] [제안: 형태]

**목적**: 어느 화면에서든 가장 잦은 입력 4가지를 3탭 안에 시작.

**항목** (순서 고정, 사용 빈도순 추정)

| 항목 | 아이콘 | 여는 화면 |
|---|---|---|
| 지출 | `wallet` | 지출 입력 (SCR-FIN-03) |
| 목표 체크 | `circle-check` | 오늘 트래커 체크 시트 (§1.2.1) |
| 일정 | `calendar-plus` | 일정 추가 (SCR-CAL-03) |
| 기록 | `pen-line` | 하위 선택: 일기 / 작품 / 위시 / 건강 |

**레이아웃**
- 모바일: 하단 오른쪽 56px 원형 버튼(하단 탭 위 16px). 누르면 `Drawer`에 4개 항목을 큰 버튼(2×2 격자, 각 72px)으로.
- PC: 상단바 `[+ 추가]` 버튼 → `DropdownMenu` 4개 항목 + 각 단축키 표시(`E` 지출, `T` 체크, `C` 일정, `J` 일기). `N` 키로 메뉴 열기.

**컴포넌트 선정 이유**: 모바일 Drawer는 엄지 영역에서 큰 터치 영역을 주고, PC DropdownMenu는 마우스 이동이 짧고 단축키를 함께 보여 줄 수 있다.

**맥락 기본값**: 현재 영역의 항목을 맨 위로 올리지 않는다(순서가 바뀌면 근육 기억이 깨짐). 대신 현재 화면이 일정의 특정 날짜면 일정 추가 시 그 날짜를 미리 채운다.

#### 1.2.1 오늘 목표 체크 시트

- 모바일 Drawer / PC Popover(상단바 버튼 아래).
- 이번 달 트래커 항목을 목록으로, 각 행 오른쪽에 오늘 칸(색 사각형 44px). 탭하면 색 채움.
- 행 길게 누르기(모바일)·`메모` 아이콘(PC): 오늘 칸 메모 입력.
- 빈 상태: "이번 달 트래커 항목이 없어요" `[트래커로 가기]`.

### 1.3 검색·빠른 실행 (SCR-CMD) [제안] P1

| 폭 | 형태 |
|---|---|
| PC | `Command` 팔레트를 `Dialog` 안에 (⌘K). 입력 즉시 결과 그룹: `바로 실행`, `일정`, `목표`, `지출`, `기록`, `위시`, `설정` |
| 모바일 | 상단 검색 아이콘 → 전체 화면 검색 페이지(입력 + 최근 검색 + 결과 그룹) |

- 바로 실행 예: "지출 추가", "이번 달 예산", "고정 지출", "다크 모드로 바꾸기", "펫 숨기기".
- 건강 기록은 검색 결과에서 기본 제외(설정 `건강 기록도 검색`이 켜져 있고 잠금 해제 상태일 때만).
- 결과 항목: 아이콘 · 제목 · 보조 정보(날짜·금액) 한 줄. 키보드 ↑↓, Enter 이동.
- 빈 결과: "'키워드'에 맞는 결과가 없어요".

### 1.4 알림 센터 (SCR-NOTI) [확정: 펫이 필요한 정보 알림] [제안: 센터]

**목적**: 놓친 알림을 모아 보기. 펫 말풍선은 순간적이므로 같은 내용이 여기에도 남는다.

| 알림 종류 | 예시 문구 | 누르면 |
|---|---|---|
| 일정 임박 | "30분 뒤 · 주간 계획 정리" | 일정 상세 |
| 결제 예정 | "내일 넷플릭스 13,500원 결제" | 고정 지출 상세 |
| 해지 예정 | "12월 15일 넷플릭스 해지 예정이에요" | 고정 지출 상세 |
| 목표 체크 누락 | "어제 영어 공부를 체크하지 않았어요" | 트래커(어제 열로 스크롤) |
| 예산 주의 | "식비 예산의 85%를 썼어요" | 예산 화면 |
| 카드 실적 | "A카드 이번 달 실적까지 52,000원 남았어요" | 카드 상세 |
| 자동 기록 | "넷플릭스 13,500원을 지출로 기록했어요" | 지출 상세 |
| 연동 문제 | "구글 캘린더 연결이 끊겼어요" | 외부 캘린더 설정 |
| 생리 예정 | "생리 예정일이 3일 남았어요" (건강 알림 켠 경우만) | 건강 |

**레이아웃**: PC `Popover`(폭 380px, 최대 높이 480px, Scroll Area) / 모바일 전체 화면. 상단 `모두 읽음`, 오른쪽 톱니(알림 설정으로). 날짜 그룹(오늘·어제·이번 주). 읽지 않은 항목은 왼쪽 점.

**상태**: 빈 상태 "새 알림이 없어요"(펫 잠자는 그림).

**보존**: 30일 지나면 목록에서 사라짐(데이터는 정책에 따라 보관). [제안]

## 2. 계정 화면

### 2.1 로그인 (SCR-AUTH-01) [확정: 아이디 로그인 + 카카오·네이버]

**목적**: 빠르게 로그인. 간편 로그인을 가장 쉽게.

**정보 우선순위**

| 등급 | 항목 |
|---|---|
| A | 카카오로 시작하기, 네이버로 시작하기, 아이디·비밀번호 입력, 로그인 버튼 |
| B | 로그인 유지(기본 켬), 회원가입 링크 |
| C | 비밀번호 찾기 |
| E | 인증 방식 설명, 토큰 관련 정보 |

**레이아웃**

```
모바일                               PC (가운데 카드 400px, 배경에 펫 일러스트)
┌───────────────────────┐          ┌──────────────────────────────┐
│      (펫 일러스트)       │          │          서비스 로고           │
│      서비스 로고         │          │  [ 카카오로 시작하기 ]          │
│                       │          │  [ 네이버로 시작하기 ]          │
│ [ 카카오로 시작하기 ]    │          │  ────── 또는 ──────            │
│ [ 네이버로 시작하기 ]    │          │  아이디 [            ]         │
│ ────── 또는 ──────     │          │  비밀번호 [          ] 👁        │
│ 아이디 [           ]   │          │  ☑ 로그인 유지                  │
│ 비밀번호 [         ] 👁 │          │  [        로그인        ]       │
│ ☑ 로그인 유지           │          │  회원가입 · 비밀번호 찾기         │
│ [      로그인      ]    │          └──────────────────────────────┘
│ 회원가입 · 비밀번호 찾기  │
└───────────────────────┘
```

**구성 요소**

| 요소 | 컴포넌트 | 이유 |
|---|---|---|
| 간편 로그인 버튼 | `Button` (카카오: 공식 노란색·심볼, 네이버: 공식 초록색·심볼) | 각 사 디자인 가이드 준수 필수(검수 대상). 테마 색을 쓰지 않음 |
| 입력 | `Field` + `Input`, 비밀번호 보기 토글(`Input Group` 아이콘 버튼) | |
| 로그인 유지 | `Checkbox` | 폼 제출과 함께 적용되므로 Switch가 아닌 Checkbox |
| 오류 | 폼 상단 `Alert`(작게) | 아이디/비밀번호 중 무엇이 틀렸는지 구분하지 않음(보안) |

**인터랙션**
- 아이디 칸에서 Enter → 비밀번호 칸, 비밀번호 칸에서 Enter → 로그인.
- 간편 로그인 → 해당 사 인증 화면 → 돌아오면 §2.3 처리.
- 연속 실패 5회: 버튼 비활성 + "잠시 후 다시 시도해 주세요 (5분)" 카운트다운. [제안]

**화면 문구**
- 오류: "아이디 또는 비밀번호가 맞지 않아요"
- 간편 로그인 취소 시: (오류 아님, 아무 표시 없음)
- 간편 로그인 실패: "카카오 로그인을 완료하지 못했어요. 다시 시도해 주세요"

### 2.2 회원가입 (SCR-AUTH-02) [확정: 이메일이 아닌 개인 아이디]

**목적**: 아이디·비밀번호만으로 가입. 이메일은 선택.

**필드**

| 필드 | 필수 | 규칙 [제안] | 실시간 표시 |
|---|---|---|---|
| 아이디 | 필수 | 4~20자, 영문 소문자·숫자·`_`·`.`, 시작은 영문, 대문자는 자동 소문자 | 입력 멈춘 뒤 0.4초에 중복 확인: "사용할 수 있어요" / "이미 쓰는 아이디예요" |
| 비밀번호 | 필수 | 8자 이상, 영문·숫자 포함(특수문자 선택), 아이디와 같으면 불가, 흔한 비밀번호 목록 차단 | 조건 체크 목록(HintText 2줄, 충족 시 체크) |
| 비밀번호 확인 | 필수 | 일치 | 불일치 시 필드 아래 오류 |
| 표시 이름 | 선택 | 1~20자 | 비우면 아이디 사용 |
| 이메일 | 선택 | 형식 검사 | HintText: "비밀번호를 잊었을 때 찾을 수 있어요" |
| 약관 동의 | 필수(공개 단계) | 1단계(본인 전용)에는 생략 가능 [제안] | `Checkbox` + 전문 보기(`Dialog`) |

**레이아웃**: 모바일 전체 화면 1열, 하단 고정 `[가입하기]`. PC 가운데 카드 440px.

**컴포넌트**: `Field`(라벨·설명·오류 자리 고정으로 레이아웃 흔들림 방지), `Input`, `Checkbox`, `Dialog`(약관 전문 — 길어도 가입 흐름을 떠나지 않게).

**상태**: 제출 중 버튼 Spinner. 서버 오류 시 상단 Alert + 입력값 유지(비밀번호 제외).

**가입 직후**: 온보딩(§2.4)으로.

### 2.3 간편 로그인 처리·계정 연결 (SCR-AUTH-03)

**흐름** [제안] (근거: [19 §3](19-integration-research.md#3-카카오-로그인--네이버-로그인))

```
카카오/네이버 인증 완료
  ├─ 이 간편 로그인이 이미 어떤 계정에 연결됨 → 로그인 → 홈
  ├─ 연결된 계정 없음 + 현재 로그인 상태 아님
  │     → "처음 오셨나요?" 화면
  │        [새로 시작하기]  (간편 로그인만으로 계정 생성. 아이디·비밀번호를 요구하지 않음 — 네이버 검수 조건)
  │        [기존 계정에 연결하기] → 아이디·비밀번호 로그인 → 연결 완료
  └─ 현재 로그인 상태에서 설정 > 연결된 로그인 > 연결하기로 온 경우
        ├─ 다른 계정에 이미 연결된 간편 로그인 → 오류 "이미 다른 계정에 연결된 카카오 계정이에요"
        └─ 아니면 연결 → 토스트 "카카오 로그인을 연결했어요"
```

- 이메일이 같다는 이유로 자동 병합하지 않는다(계정 탈취 위험). [제안]
- 간편 로그인으로 만든 계정은 아이디가 없다. 설정에서 원하면 나중에 아이디·비밀번호를 추가할 수 있다. [제안]

**"처음 오셨나요?" 화면 구성**: 펫 일러스트 + 제목 "처음 오셨나요?" + 버튼 2개(위: `default` 새로 시작하기, 아래: `outline` 기존 계정에 연결하기) + HintText "이미 아이디로 가입했다면 연결해 주세요".

### 2.4 온보딩 (SCR-AUTH-04) [제안]

**목적**: 처음부터 모든 설정을 요구하지 않는다. 최대 3단계, 모두 건너뛰기 가능.

| 단계 | 내용 | 컴포넌트 |
|---|---|---|
| 1 | "뭐라고 불러 드릴까요?" 표시 이름 | `Input` |
| 2 | "주로 무엇을 관리하실 건가요?" 영역 선택(복수): 목표, 돈, 일정, 기록, 건강 | `Toggle Group`(type=multiple, 큰 카드형 토글, 아이콘+라벨) |
| 3 | "함께할 펫을 골라 주세요" 5종 + `나중에` | `Radio Group`(카드형, 펫 미리보기 애니메이션) |

- 상단 진행 표시 점 3개, 오른쪽 위 `건너뛰기`.
- 완료 시 홈. 선택한 영역의 위젯만 홈에 켜진다. 펫을 고르면 홈 진입 시 펫이 화면 가장자리에서 걸어 들어온다(움직임 줄이기 설정 시 그냥 나타남).
- 모바일 전체 화면, PC 가운데 카드 520px.

| 일정 없는 달 | 격자는 그대로, 선택일 목록에 "일정이 없어요" `[일정 추가]` |
| 외부 캘린더 가져오는 중 | 상단 얇은 진행 띠 + "구글 캘린더에서 가져오는 중" (화면 사용 가능) |
| 외부 연결 끊김 | 상단 InlineNotice "구글 캘린더 연결이 끊겼어요" `[다시 연결]`, 해당 일정은 흐리게 + 마지막 동기화 시각 |
| 오프라인 | 캐시된 달만 표시, 다른 달 이동 시 "오프라인이라 불러올 수 없어요" |

### 4.2 일정 상세 (SCR-CAL-02)

| 항목 | 표시 |
|---|---|
| 제목 | `text-title` |
| 날짜·시간 | "11월 1일 (일) 오후 2:00 ~ 3:00" / 종일 "11월 1일 (일) 종일" |
| 반복 | 🔁 "매주 일요일" |
| 알림 | 🔔 "30분 전" |
| 장소 | 📍 장소 텍스트(지도 링크는 P2) |
| 메모 | 본문 |
| 캘린더 | 색 점 + 이름 ("내 일정", "구글 · 회사") |
| 출처 | 외부 일정이면 "구글 캘린더에서 가져온 일정" + 읽기 전용이면 `lock` 아이콘 |

- 하단(모바일)·상단 오른쪽(PC): `[수정]`(outline) + `···`(복제, 삭제).
- 외부 읽기 전용 일정: 수정·삭제 버튼 대신 "구글 캘린더에서 수정해 주세요" + `[구글 캘린더에서 열기]`(외부 링크).

**연결 후 카드 내용 (구글 예)**

| 항목 | 컴포넌트 |
|---|---|
| 연결된 계정 | 텍스트 + `···`(연결 해제) |
| 가져올 캘린더 목록 | `Checkbox` 목록(색 점 + 이름) |
| 방식 | `Radio Group`: `가져오기만` (외부 일정은 읽기 전용) / `함께 고치기` (양쪽 반영) + 각 한 줄 설명. ⓘ "구글에서 바꾼 일정은 15분마다, 그리고 앱을 열 때 가져와요" (D-043, 실시간 푸시 없음) |
| 이 앱 일정 보낼 곳 | `Select` (함께 고치기 선택 시만) |
| 마지막 동기화 | "5분 전" + `[지금 가져오기]` |

- ⓘ (네이버): "네이버 캘린더는 일정 추가만 지원해요. 네이버에서 만든 일정은 이 앱으로 가져올 수 없어요. 가져오기가 필요하면 고급 연결을 써 보세요." + `자세히 보기`(가이드: CalDAV 고급 연결) [검증 반영]
- 고급 연결(네이버 CalDAV)은 1단계 본인 전용·[검증 필요] 옵션으로 가이드 안에서만 진입한다. 입력: 네이버 아이디, 애플리케이션 비밀번호. 경고 InlineNotice: "네이버 2단계 인증의 애플리케이션 비밀번호를 사용해요. 네이버 로그인 비밀번호를 넣지 마세요." 이 입력은 사용자가 직접 한다.
- 연결 해제: `Alert Dialog` "구글 캘린더 연결을 해제할까요?" 본문 "가져온 일정은 이 앱에서 사라져요. 구글 캘린더의 일정은 그대로예요." `[취소] [연결 해제]`.

### 5.1 월간 트래커 (SCR-GOAL-02) [확정: 핵심 요구]

**목적**: 이번 달 매일 할 일의 달성 여부를 날짜별로 칸 색으로 체크하고, 칸 안에 짧은 메모를 남긴다.

**확정 요구 요약**
- 목표(항목)가 한 축, 해당 월의 날짜가 한 축.
- 체크박스가 아니라 칸을 체크하면 배경색이 바뀐다.
- 관련 메모는 그 칸 안에 텍스트로 입력된다.
- 목표별 배경색을 다르게 설정. 색상 팔레트 제공 필수.

**정보 우선순위**

| 등급 | 항목 |
|---|---|
| A | 항목 이름(행 머리), 날짜(열 머리), 칸 색(완료 여부), 오늘 열 강조 |
| B | 칸 안 메모(1~2줄 말줄임), 요일, 항목별 완료 수 `12/30` |
| C | 메모 전문(Tooltip/Popover), 항목 설명, 연결된 목표 |
| D | 사용법(? : 칸 누르기·메모·색 바꾸기) |
| E | 칸 상태 내부 코드, 정렬 키 |

**칸 동작** [확정: 색 채움·칸 안 메모] [제안: 조작 방식]

| 동작 | PC | 모바일 | 결과 |
|---|---|---|---|
| 완료 ↔ 미완료 전환 | 클릭 | 탭 | 배경색 채움/비움(120ms), 낙관적 저장 |

| 메모만 있고 미완료 | 가능 | 가능 | 칸 배경은 비움, 글자만 표시 (예: "쉼" 메모) |

| 미래 날짜 | 클릭해도 변화 없음, 커서 기본 | 탭해도 변화 없음 | 흐린 배경(`muted` 50%) |
| 과거 날짜 | 수정 가능 | 수정 가능 | |
| 키보드 | 화살표 이동, Space 전환, Enter 메모, Esc 선택 해제 | — | `role="grid"` |

- 이번 달에 항목이 없고 지난달에 항목이 있으면 빈 상태 대신: "지난달 항목으로 시작할까요?" + 지난달 항목 목록(색 점 + 이름, 각 `Checkbox` 기본 선택) + `[이대로 시작]` `[새로 만들기]`. [제안]
- 이 동작은 해당 월에 처음 들어올 때 자동으로 실행되지 않는다(사용자가 고른다).

**상태**
| 상태 | 표현 |
|---|---|
| 첫 사용 | 펫 일러스트 + "매일 체크할 일을 추가해 보세요" + 예시 칩 `독서` `운동` `물 마시기` (탭하면 그 이름으로 추가 Dialog) + `[항목 추가]` |
| 로딩 | 표 모양 Skeleton(항목 3행) |
| 오류 | "트래커를 불러오지 못했어요" `[다시 시도]` |

**사용법(?) Popover 내용**
1. 칸을 누르면 색이 채워져요.
2. PC는 두 번 클릭, 모바일은 길게 눌러 메모를 남겨요.
3. 항목 이름을 누르면 색을 바꿀 수 있어요.

**데이터 연결**
- 항목에 목표를 연결하면 목표 상세에 "이번 달 실천 12/30일"이 표시된다.
- 홈 "오늘의 목표" 위젯과 빠른 추가 "목표 체크"는 같은 칸 데이터를 쓴다.
- 독서 항목과 작품 기록은 자동 연결하지 않는다(서로 다른 의미: 매일 읽기 습관 vs 책 한 권 기록). [제안]

### 6.2 지출 목록 (SCR-FIN-02)

**목적**: 기록한 지출·수입을 찾고 고친다.

**레이아웃**

**그릇**: 모바일 `Drawer`(키패드 영역 포함 전체 높이에 가깝게) / PC `Dialog sm~md`.

```
모바일 Drawer
┌─────────────────────────┐
│ (지출|수입)          [닫기] │
│                         │
│          12,000원        │  ← 큰 금액 표시, 숫자 키패드(시스템) 자동
│                         │
│ 분류  [식비][카페][교통][쇼핑][···] │ ← 최근 사용순 칩 6개 + 더 보기
│ 결제  [A카드][B카드][현금][···]    │
│ 날짜  오늘 ▾               │
│ 내용  [점심            ]   │  ← 선택. 비우면 분류 이름 표시
```

| 필드 | 컴포넌트 | 필수 | 기본값 | 비고 |
|---|---|---|---|---|
| 지출/수입 | `Toggle Group` | | 지출 | |
| 금액 | `AmountInput` (inputmode numeric, 쉼표 실시간) | 필수 | — | 자동 포커스. 0원 불가 |
| 분류 | `QuickChips` + 더 보기 `Combobox`(새 분류 만들기 포함) | 필수 | 없음(직전 선택 기억 안 함: 오기록 방지) [제안] | 수입이면 수입 분류(급여, 용돈, 환급 등) |
| 결제수단 | `QuickChips` | 선택 | 마지막 사용 | 카드 혜택 분석에 필요 → 비워 두면 분석 제외 |
| 날짜 | 버튼 → `Popover`/`Drawer` + `Calendar` | | 오늘 | 시간은 기록하지 않음(선택: 설정에서 시간 기록 켜기) [제안] |
| 내용 | `Input` | 선택 | — | 가맹점·내용. 자동 완성: 과거 내용 + 그때의 분류 제안 |
| 메모 | `Textarea` | 선택 | — | 접힘 |
| 큰 지출 연결 | `Select` (이번 달 큰 지출 목록) | 선택 | — | 접힘. 예: "여행" 계획에 연결 |
| 할부 | `Select`(일시불/2~24개월) | 선택 | 일시불 | 접힘. 카드 실적·혜택 계산 반영 [제안] |
| 사진(영수증) | `UploadDropzone` | 선택 | — | 접힘, P2 |

**내용 자동 완성** [제안]: "스타벅스" 입력 시 과거 기록에서 분류 "카페"를 제안 칩으로 보여 준다(자동 선택하지 않음, 탭으로 확정).

**저장 후**
- 토스트 "지출을 기록했어요 · 되돌리기". 이 저장으로 예산을 넘기면 토스트 대신 "식비 예산을 12,000원 넘었어요 · 그만큼 참아야 할 금액에 더해져요" (warning, 5초).
- 사치 분류(참은 소비에 포함된 분류)로 저장하면 "사치 지출을 기록했어요 · 이번 달 참아야 할 금액 +50,000원" + `참은 소비 보기`. [20 §5.1]
- `연속 입력` 옵션(Drawer 하단 Checkbox): 켜면 저장 후 폼을 비우고 다시 금액 칸에 포커스. [제안]

**수정 시**: 같은 폼 + 하단 `삭제`(ghost, destructive-text) + 머리 `변경 기록`(link). 위시·고정 지출에서 만든 지출은 상단에 출처 칩("위시에서 구매", "고정 지출 자동 기록") — 탭하면 원본으로.

**검증·오류**
- 금액 미입력 시 저장 버튼 비활성(오류 문구 없음, 버튼 상태로 충분).
- 분류 미선택 시 저장 탭하면 분류 칩 아래 "분류를 골라 주세요".
- 미래 날짜: 허용(예정 지출), 날짜 옆에 "예정" 배지. [제안]

### 6.4 월별 예산 (SCR-FIN-04) [확정: 월별 예산, 큰 지출 개별 입력, 나머지는 범위별 예산]

**목적**: 이번 달 예산을 보고 분류별 사용 상태·큰 지출 사용 여부를 확인.

**정보 우선순위**

| 등급 | 항목 |
|---|---|
| A | 총예산·쓴 돈·남은 돈, 분류별 예산 대비 사용(초과 표시), 큰 지출 항목별 사용 여부 |
| B | 고정 지출 합계(자동), 분류별 남은 금액 |
| C | 분류별 지출 내역(펼침) |
| D | 범위별 예산·큰 지출 설명(ⓘ) |

**레이아웃**

```
┌────────────────────────────────────────────────┐
│ [<] 11월 예산 [>]                         [예산 수정] │
│ 800,000원 중 426,000원 썼어요 · 374,000원 남음        │
│ ━━━━━━━━━━━━━━━──────────────                     │
├────────────────────────────────────────────────┤
│ 고정 지출 ⓘ                       148,500원 (자동)   │
│ ▸ 넷플릭스, 통신비, 네이버플러스 …                    │
├────────────────────────────────────────────────┤
│ 이번 달 큰 지출 ⓘ                                  │
│ 여행          300,000원   사용 280,000원 ✔          │
│ 부모님 선물    100,000원   아직 안 씀                 │
├────────────────────────────────────────────────┤
│ 분류별 예산 ⓘ                                      │
│ 식비   182,000 / 250,000   ━━━━━━━━━━──   68,000 남음 │
│ 쇼핑   132,000 / 100,000   ━━━━━━━━━━━━  32,000 초과 ⚠ │
│ ▸ 펼치면 해당 분류 지출 목록                           │
│ 예산 없는 분류  기타 12,000원                          │
└────────────────────────────────────────────────┘
```

- 고정 지출 합계는 그 달 결제 예정·완료 고정 지출의 합(해지 예정은 마지막 이용일까지 결제분만 포함).
- 큰 지출 "사용 여부": 연결된 지출 합계로 판단. 0원 = "아직 안 씀", 일부 = 금액, 계획 이상 = "초과". 사용자가 수동으로 "다 썼어요" 체크도 가능. [제안]
- 분류 행 `Collapsible`로 지출 목록 펼침(최근 5건 + `전체 보기`).
- 모바일: 같은 구조 1열. 막대와 숫자를 두 줄로.

**ⓘ 문구**
- 큰 지출: "여행·경조사처럼 이번 달에만 크게 나가는 돈이에요. 따로 적어 두면 분류별 예산이 흔들리지 않아요."
- 분류별 예산: "식비·교통처럼 매달 비슷하게 쓰는 돈의 한도예요."
- 고정 지출: "고정 지출에 등록한 금액이 자동으로 더해져요."

### 6.5 예산 편집 (SCR-FIN-05)

**그릇**: PC `Dialog lg` / 모바일 전체 화면(항목이 많아 Drawer 부적합).

| 영역 | 입력 |
|---|---|
| 큰 지출 | 행 추가: 이름 `Input` + 금액 `AmountInput` + 삭제. `[+ 큰 지출 추가]` |
| 분류별 예산 | 분류마다 금액 `AmountInput`(빈칸 = 예산 없음). 분류 추가는 Combobox |
| 합계 | 하단 고정: "고정 148,500 + 큰 지출 400,000 + 분류별 650,000 = 1,198,500원" |
| 빠른 채우기 | `[지난달 예산 복사]` `[지난달 실제 지출로 채우기]` (outline) |

- "다음 달에도 같은 예산 쓰기" `Checkbox`(기본 켬): 켜면 다음 달 첫 진입 시 이 분류별 예산을 복사(큰 지출은 복사 안 함). [제안]
- 저장: `[예산 저장]`. 이번 달이 지난 달(과거)의 예산 수정은 허용하되 상단 InlineNotice "지난 달 예산을 고치고 있어요".

### 6.6 고정 지출 목록 (SCR-FIN-06) [확정: 고정 지출 저장, 건별 메모, 해지 관리]

**목적**: 매달·매년 나가는 돈과 각 항목의 메모(포함 혜택 등)를 확인하고, 해지를 관리한다.

**해지 관리 설계** (사용자 질문: "목록에서 빼도 되나? 해지 표시하고 맨 밑으로?") [제안]

| 상태 | 화면 위치 | 표시 | 예산·알림 |
|---|---|---|---|
| 이용 중 | 위쪽 기본 목록(다음 결제일순) | 이름 · 금액 · 다음 결제일 | 포함 |
| 해지 예정 | 기본 목록에 그대로(결제일순 유지) | `해지 예정` 배지(warning) + "12월 15일까지" | 마지막 이용일 전 결제분만 포함. 마지막 이용일 3일 전 알림 |
| 해지됨 | 맨 아래 `해지됨 3` 묶음(Collapsible, 기본 접힘) | 흐린 글자 + 해지일 | 제외 |

- **삭제가 아니라 상태 변경**이다. 해지된 항목도 메모·결제 이력이 남아 "언제 얼마까지 냈는지", "다시 가입할지" 판단에 쓰인다. 다시 이용하면 `다시 이용하기`로 이용 중으로 되돌린다.
- 완전히 지우고 싶으면 `···` → 삭제(휴지통). 해지와 삭제를 구분한다.

**레이아웃**

```
PC
┌───────────────────────────────────────────────────────────┬──────────┐
│ 고정 지출  월 148,500원 · 연 환산 1,782,000원      [+ 추가]  │ 상세 Sheet │
├───────────────────────────────────────────────────────────┤          │
│ 이름          금액        주기     다음 결제     결제수단   메모  │          │
│ 넷플릭스      13,500원    매월 3일  11/3 (화)   A카드     📝   │          │
│   해지 예정 · 12월 15일까지                                    │          │
│ 통신비        55,000원    매월 5일  11/5 (목)   계좌      —    │          │
│ 네이버플러스   4,900원     매월 20일 11/20       B카드     📝   │          │
│ ▸ 해지됨 3                                                    │          │
└───────────────────────────────────────────────────────────┴──────────┘

모바일
┌─────────────────────────┐
│ 월 148,500원        [+]   │
├─────────────────────────┤

│ 11/3 · 해지 예정 12/15     │
│ 통신비          55,000원  │
│ 11/5 · 계좌               │

└─────────────────────────┘
```

**구성 요소**

| 요소 | 컴포넌트 | 이유 |
|---|---|---|
| 목록 | PC `Table`(정렬: 다음 결제일·금액·이름) / 모바일 `Item` | 비교 열이 5개라 PC는 표 |
| 메모 표시 | `sticky-note` 아이콘 + PC `Hover Card`(메모 전문 미리보기) / 모바일 행 아래 첫 줄 미리보기(1줄 말줄임, 설정으로 끄기) | 메모가 핵심 정보이므로 모바일에서도 첫 줄은 노출 [확정 맥락: 포함 혜택 메모를 봐야 중복 결제를 막음 — 화면 문구에는 이유를 쓰지 않음] |
| 해지 예정 | `Badge` + 날짜 | 행동에 영향 주는 정보는 숨기지 않음 [확정 원칙] |
| 해지됨 묶음 | `Collapsible` | 끝난 항목은 접어 둠 |
| 합계 | 머리 문구 | 월·연 환산 |

**상태**: 빈 상태 "매달 나가는 돈을 등록해 보세요" `[고정 지출 추가]` + 예시 칩(`넷플릭스`, `통신비`, `보험`).

### 6.7 고정 지출 상세·추가·수정·해지 (SCR-FIN-07)

**추가·수정 폼** (`ResponsiveModal`)

| 필드 | 컴포넌트 | 필수 | 비고 |
|---|---|---|---|
| 이름 | `Input` | 필수 | 자동 완성: 자주 쓰는 구독 이름 목록(넷플릭스, 유튜브 프리미엄 …) [제안] |
| 금액 | `AmountInput` | 필수 | |
| 주기 | `Select`: 매월 / 매년 / N개월마다 / 매주 | 필수 | ⓘ "매월 31일처럼 없는 날은 그 달 마지막 날에 결제돼요" |
| 결제일 | 매월: 일 `Select`(1~31, 말일) / 매년: 월·일 / N개월: 시작 월 + 일 | 필수 | |
| 결제수단 | `Select`(등록 결제수단) | 선택 | 카드 실적 계산에 사용 |
| 분류 | `Combobox` | 선택 | 기본 "구독·고정"(예산 분류) |
| 메모 | `Textarea` | 선택 | placeholder "예: 넷플릭스 이용권 포함" [확정: 메모 필요] |
| 결제일 알림 | `Switch` | | 기본 켬(1일 전) |
| 자동 기록 | `Switch` + ⓘ | | 기본 끔. "결제일에 지출로 자동 기록해요. 금액이 다르면 나중에 고칠 수 있어요." P1 |
| 시작일 | 날짜 | 선택 | 기본 오늘. 이력 계산용 |

**상세 화면 내용**

| 영역 | 내용 |
|---|---|
| 머리 | 이름, 상태 배지, 금액, 주기 "매월 3일" |
| 다음 결제 | "11월 3일 (화)" — 크게 [확정 원칙: 다음 결제일은 숨기지 않음] |
| 메모 | 전문(첫 화면에 노출) |
| 결제 이력 | 자동 기록·연결된 지출 목록(최근 6회), 총 납부액 |
| 작업 | `[수정]`, `[해지 예정으로 바꾸기]`(outline), `···`(바로 해지됨으로, 복제, 삭제) |

**해지 예정 처리 흐름**
1. `[해지 예정으로 바꾸기]` → `Dialog sm`: "언제까지 이용하나요?" + 날짜(`Calendar`, 기본: 다음 결제일 전날) + HintText "이 날 이후에는 결제 예정에서 빠져요".
2. `[해지 예정으로 바꾸기]` → 상태 변경, 토스트 "12월 15일에 해지돼요 · 되돌리기".
3. 마지막 이용일이 지나면 자동으로 `해지됨` 묶음으로 이동(서버 일일 작업).
4. 해지 예정 취소: 상세에서 `해지 취소`.

- 해지 처리에 Alert Dialog를 쓰지 않는 이유: 되돌릴 수 있고(상태 변경), 실제 구독 해지는 외부 서비스에서 하는 일이다. 앱에서는 기록일 뿐이다.
- 상세 하단 InlineNotice(해지 예정일 때): "실제 해지는 해당 서비스에서 직접 해 주세요." [제안]

### 6.8 카드 목록 (SCR-FIN-08) [확정: 카드 혜택 관리]

**목적**: 내 카드들의 이번 달 실적 충족과 남은 할인 한도를 한눈에 보고, 혜택을 관리한다.

**정보 우선순위**

| 등급 | 항목 |
|---|---|
| A | 카드 이름, 이번 달 실적 진행(조건 충족 여부), 남은 혜택 한도 |
| B | 대표 혜택 2~3개, 결제일 |
| C | 전체 혜택·조건(카드 상세) |
| D | 실적·한도·제외 대상 용어 정의(ⓘ) |
| E | 혜택 규칙의 내부 구조 |

**레이아웃**

```
PC (카드 격자 2~3열)                                  [어떤 카드 쓸까?] [+ 카드 추가]
┌──────────────────────────┐ ┌──────────────────────────┐
│ A카드 (○○카드)        ···  │ │ B카드                  ···  │
│ 이번 달 실적 ⓘ              │ │ 이번 달 실적                │
│ 248,000 / 300,000원        │ │ 312,000 / 300,000원 ✔      │
│ ━━━━━━━━━━━━━────  52,000 남음 │ │ ━━━━━━━━━━━━━━━━━ 충족        │
│ 할인 한도  6,000 / 10,000원 │ │ 할인 한도 10,000 / 10,000 다 씀│
│ 영화 · 카페 · 편의점          │ │ 주유 · 통신                 │
└──────────────────────────┘ └──────────────────────────┘
                     최종 확인일: 2026-10-20 (작게, 혜택을 마지막으로 확인한 날)

모바일: 카드 1열, 같은 내용. 상단 [어떤 카드 쓸까?] 버튼 전체 폭.
```

- "이번 달 실적": 이 카드로 결제수단을 지정한 지출의 실적 인정 금액 합계. 실적 기준 기간(전월 1일~말일 등)은 카드 설정을 따른다. 실적 제외 업종(설정한 경우)은 빼고 계산. → [06 §6](06-finance.md)
- 지출에 결제수단을 넣지 않은 경우가 많으면 카드 위에 InlineNotice: "결제수단이 없는 지출 12건은 실적에 포함되지 않았어요" `[지출 확인]`. [확정 맥락: 입력이 부실하면 사용자가 직접 판단]
- 최종 확인일: 카드사 혜택이 바뀔 수 있으므로 표시. 90일 지나면 "혜택이 바뀌었는지 확인해 보세요" (warning, 작게). [검증 반영]

### 6.9 카드 상세 (SCR-FIN-09)

| 영역 | 내용 | 컴포넌트 |
|---|---|---|
| 머리 | 카드 이름, 카드사, 결제일, 연회비(선택), `[수정]` `···` | |
| 실적 | 이번 달 실적 막대, 전월 실적(이번 달 혜택 적용 구간 결정에 쓰임) "지난달 312,000원 → 이번 달 30만원 구간 혜택" | `Progress` + ⓘ |
| 혜택 목록 | 혜택마다 행: 대상(가맹점·업종) · 내용("10% 할인, 최대 5,000원/월") · 이번 달 사용 `3,000 / 5,000원` | `Item` + 작은 `Progress` |
| 혜택 조건 | 행 펼침: 전월 실적 구간, 최소 결제 금액, 요일·시간, 횟수, 제외 조건, 메모 | `Collapsible` |
| 실적 제외 | 실적 인정 안 되는 업종 목록 | `Accordion` 하나 |
| 이번 달 혜택 받은 지출 | 지출 목록(예상 할인액 표시) | `Item` |
| 메모 | | |
| 하단 | `[+ 혜택 추가]`, `[혜택 문구로 한 번에 추가]`(AI) | |

ⓘ 용어 정의(InfoTip 문구 초안)
- 실적: "카드로 쓴 금액 중 혜택 조건 계산에 인정되는 금액이에요. 보통 할부·상품권·세금 등은 빠져요."
- 전월 실적 구간: "지난달 실적에 따라 이번 달에 받을 수 있는 혜택이 달라져요."
- 할인 한도: "한 달 동안 받을 수 있는 할인의 최대 금액이에요."

### 6.10 혜택 추가·수정 (SCR-FIN-10) [확정: 혜택 저장] [검증 반영: 공개 API 없음 → 직접 입력 + AI 붙여넣기]

**두 가지 진입**

| 진입 | 흐름 |
|---|---|
| `[+ 혜택 추가]` | 한 개 혜택을 직접 입력 |
| `[혜택 문구로 한 번에 추가]` | 카드사 안내 문구를 붙여넣기 → AI가 혜택 목록 초안 생성 → 사용자가 항목별 확인·수정 → 선택한 것만 저장. AI 미연결 시 버튼은 보이되 누르면 "AI를 연결하면 쓸 수 있어요" `[AI 연결]` |

**직접 입력 폼** (`ResponsiveModal`, PC Dialog md / 모바일 전체 화면)

| 필드 | 컴포넌트 | 필수 | 비고 |
|---|---|---|---|
| 대상 | `Toggle Group`: 가맹점 / 업종 → 가맹점: 태그 입력(CGV, 메가박스…, 자동 완성) / 업종: `Combobox`(영화, 카페, 편의점, 주유, 통신, 대중교통…) | 필수 | |
| 혜택 종류 | `Toggle Group`: 할인 / 적립 / 캐시백 | 필수 | |
| 혜택 크기 | `Toggle Group`: % / 원 + 숫자 `Input` | 필수 | 예: 10%, 4,000원 |
| 1회 최대 | `AmountInput` | 선택 | |
| 월 한도 | `Toggle Group`: 금액 / 횟수 / 없음 + 값 | 선택 | 다른 혜택과 한도를 함께 쓰면 "한도 묶음" 선택(Select: 새 묶음 / 기존 묶음) ⓘ |
| 전월 실적 조건 | `Collapsible` → 구간 행 추가: "30만원 이상 → 10%", "50만원 이상 → 15%" | 선택 | 구간 없으면 조건 없음 |
| 최소 결제 금액 | `AmountInput` | 선택 | |
| 요일·시간 | `Toggle Group`(요일 복수) + 시간 범위 | 선택 | 접힘 |
| 제외 조건 | `Textarea` 짧게 + 체크(할부 제외, 온라인 제외) | 선택 | 접힘 |
| 메모 | `Textarea` | 선택 | |

- 한 화면에 필드가 많으므로 상단 3개(대상·종류·크기)만 펼쳐 두고 나머지는 "조건 더 넣기" `Collapsible`. [확정 원칙: 설정 모달이 커지지 않게]
- ? 사용법 / 가이드 `카드 혜택 등록하기`: 예시 3개(영화 할인, 카페 적립, 전월 실적 구간 있는 혜택)를 그림으로.

**AI 붙여넣기 흐름**

```
1. 큰 Textarea: "카드사 앱이나 홈페이지의 혜택 안내 문구를 붙여넣어 주세요"
   HintText: 개인정보(카드번호 등)는 붙여넣지 마세요.
2. [혜택 찾기] → 진행 표시 "혜택을 정리하는 중…" (Skeleton 카드 3개)
3. 결과: 혜택 카드 목록. 각 카드: 체크박스(기본 선택) · 요약 한 줄 · [수정]
   불확실한 값은 warning 표시 "확인 필요: 월 한도를 찾지 못했어요"
4. [선택한 혜택 3개 저장]
```

- AI가 만든 혜택은 저장 시 출처 "붙여넣은 안내 문구"로 기록(내부: `source=ai_parse`), 원문 붙여넣기 텍스트는 사용자가 원하면 카드 메모에 저장(Checkbox 기본 끔).
- AI에게 보내는 내용은 붙여넣은 문구만(지출 데이터 포함 안 함).

### 6.11 어떤 카드 쓸까 (SCR-FIN-11) [확정: 혜택 분석·챗봇] [제안: AI 없이도 동작하는 계산 화면]

**목적**: 결제 직전에 가맹점·금액을 넣으면 카드별 예상 혜택을 비교. AI 비서도 같은 계산을 쓴다.

**레이아웃**

```
┌──────────────────────────────────────────┐
│ 어디서 결제하나요?  [ CGV            ]       │  ← 가맹점 자동 완성 + 업종 추정
│ 금액(선택)          [ 28,000원       ]       │
│ [비교하기]                                  │
├──────────────────────────────────────────┤
│ 1  A카드   예상 4,000원 할인          추천    │
│    영화 4,000원 할인 · 이번 달 1/2회 사용      │
│ 2  C카드   예상 1,400원 적립                 │
│ —  B카드   혜택 없음 · 이번 달 한도 다 씀  ▾    │
│ ⓘ 계산 기준                                 │
│ [AI에게 물어보기]                             │
└──────────────────────────────────────────┘
```

- 결과 정렬: 예상 혜택 금액. 같으면 실적이 부족한 카드 우선(실적 채우기에 도움). [제안]
- 각 결과 펼침(`Collapsible`): 적용 혜택, 남은 한도, 이 결제로 실적 충족 여부("이 결제로 이번 달 실적 30만원을 채워요").
- 금액 미입력: % 혜택은 "10% 할인" 형태로, 금액 계산은 생략.
- 데이터 부족: 카드가 0장 → "카드를 등록해 보세요" `[카드 추가]`. 혜택이 0개인 카드 → "혜택 없음(등록 안 됨)".
- `[AI에게 물어보기]`: 대화창을 열고 "CGV에서 28,000원 결제할 때 어떤 카드가 좋아?"를 미리 채워 보냄.
- 모바일: 같은 구조 1열, 입력은 상단 고정.

### 6.12 계좌·투자 (SCR-FIN-12) [확정: 재테크 영역] [제안: 수동 기록] P1

- 목록: 계좌·투자·부채 항목(이름, 종류 `Badge`, 현재 금액, 마지막 업데이트 날짜).
- 상단: 순자산 = 자산 − 부채, 월별 추이 영역 차트(`Chart`).
- 금액 업데이트: 행 탭 → `Drawer`/`Popover`로 새 금액 입력(그날 날짜로 스냅샷 기록). "한 번에 업데이트" 화면: 모든 항목 금액 칸을 한 화면에 나열(월 1회 정리용).
- 알림(선택): 매월 1일 "자산을 업데이트해 볼까요?".
- 투자 수익률 계산, 시세 연동은 범위 밖. [제안]

### 6.13 분류·결제수단 관리 (SCR-FIN-13)

- 분류: 지출 분류(이름, 아이콘, 색 점, 예산 사용 여부), 수입 분류. 순서·숨기기·삭제(사용 중이면 다른 분류로 옮기기 선택 Dialog).
- 기본 지출 분류 [제안]: 식비, 카페·간식, 교통, 쇼핑, **사치** [확정], 생활, 문화·여가, 건강·의료, 교육, 경조사·선물, 여행, 구독·고정, 기타.
- 분류 설정에 `참은 소비에 포함`(Switch + ⓘ "이 분류에 쓴 돈만큼 참은 소비 목록을 채워야 해요") — 기본은 사치만 켜짐. [20 §3]

### 6.14 참은 소비 (SCR-FIN-14) [확정: 참은 소비 목록] [제안: 화면 구성]

**목적**: 사치·예산 초과로 이번 달 얼마나 참아야 하는지 보고, 진짜 사고 싶었는데 참은 것을 기록해 그 금액을 채운다. 규칙은 [20 참은 소비](20-restraint-spending.md).

**정보 우선순위**

| 등급 | 항목 |
|---|---|
| A | 참아야 할 금액, 참은 금액, 더 참아야 할 금액(또는 달성), 진행 막대 |
| B | 참은 소비 목록(이름·금액·날짜·출처), 이번 달 말에 들어갈 위시 후보와 합계 |
| C | 참아야 할 금액 내역(사치 지출 합계, 분류별 초과액, 넘어온 금액, 나중에 산 물건), 지난 달 정산 기록 |
| D | 계산 방식·자동 포함 조건(ⓘ) |
| E | 정산 작업 상태, 계산 내부 값 |

**레이아웃**

```
PC (2열)
┌───────────────────────────────────────┬──────────────────────────────┐
│ [<] 11월 참은 소비 [>]          ⓘ      │ 이번 달 말에 들어갈 후보   ⓘ    │
│ 참아야 할 금액   182,000원  ▸ 내역      │ ▢ 무선 이어폰  갖고 싶음  89,000 │
│ 참은 금액       129,000원              │ ▢ 가죽 가방    관심     159,000 │
│ ━━━━━━━━━━━━━━━━━──────── 71%          │ 지금 이대로 사지 않으면           │
│ 53,000원 더 참아야 해요                 │ 248,000원이 채워져요            │
│                    [+ 참은 것 기록]     │ ⚠ 가격이 없는 위시 1개 [가격 넣기] │
├───────────────────────────────────────┤                              │
│ 참은 소비 목록                          │                              │
│ 11/12  한정판 운동화   직접   129,000원  │                              │
│        "비슷한 게 이미 있음"             │                              │
│ ▸ 지난달 정산 보기                       │                              │
└───────────────────────────────────────┴──────────────────────────────┘

모바일 (1열): 진행 카드 → [+ 참은 것 기록] → 참은 소비 목록 → 후보(Collapsible, 기본 펼침) → 지난달 정산
```

**구성 요소**

| 요소 | 컴포넌트 | 선정 이유 |
|---|---|---|
| 진행 카드 | `Card` + `Progress` + 큰 숫자(`text-display`) | A 등급 세 숫자를 한 묶음으로 |
| 내역 | `Collapsible` "▸ 내역": 사치 지출 139,000 · 식비 초과 18,000 · 쇼핑 초과 25,000 · 넘어온 금액 0. 각 줄 탭 → 해당 지출 목록·예산 | 숫자의 근거는 필요할 때만 |
| 계산 방식 ⓘ | `InfoTip` | "사치 분류에 쓴 돈과 분류별 예산을 넘은 금액을 더한 만큼 참아야 해요. 부족하면 다음 달로 넘어가요." |
| 목록 | `Item` (날짜 · 이름 · 출처 `Badge`[직접/위시/그만둔 위시] · 금액 · 메모 첫 줄) | |
| 후보 | `Item` + 썸네일, 구분 배지, 가격 / 머리 ⓘ "1일 전부터 담아 둔 갖고 싶음·관심 물건 중 이번 달에 사지 않은 것이 다음 달 1일에 자동으로 들어가요" | 사지 않을 동기를 보여 줌 |
| 가격 없음 경고 | `InlineNotice` + `[가격 넣기]` | 중요한 주의사항은 작업 위치에 직접 |
| 직접 기록 | `ResponsiveModal`: 이름, 금액(`AmountInput`), 날짜, 참은 이유(`Textarea`), 이미지·링크(접힘), `위시에서 고르기`(`Combobox`) | |
| 지난달 정산 | `Collapsible` → 월별 행(참아야 할 금액 · 참은 금액 · 결과 배지 달성/부족·넘김) | |

**인터랙션**
- 목록 행 탭: 수정(직접 기록) 또는 위시 상세(위시 자동). `···`: 이번 달에서 빼기(위시 자동), 삭제(직접 기록 → 휴지통).
- 후보 행 탭: 위시 상세. 후보에서 `지금 참은 것으로 기록`(link): 이번 달 직접 기록으로 바로 넣기(위시에서 고르기와 같음).
- 월 이동: 지난 달은 정산 결과 + `다시 정산`(정산 뒤 바뀐 지출이 있을 때만 보임).

**상태**
| 상태 | 표현 |
|---|---|
| 참아야 할 금액 0 | 진행 카드 대신 "이번 달은 참아야 할 금액이 없어요" + 기록은 계속 가능 |
| 달성 | 막대 가득 + "이번 달 목표만큼 참았어요" (`success` 아이콘), 펫 축하(P1) |
| 목록 비어 있음 | "참은 것을 기록해 보세요" `[+ 참은 것 기록]` |
| 후보 없음 | "다음 달에 들어갈 위시가 없어요" + `[위시 보기]` |
| 예산 미설정 | 내역에 "예산을 정하면 초과 금액도 더해져요" |
| 정산 대기 | 1일 정산 전(PC 꺼짐 등): "10월 정산을 기다리는 중이에요" |

**정산 결과 화면** (알림·펫 말풍선에서 진입, `ResponsiveModal md`)
- 제목 "10월 정산", 세 숫자, 자동으로 들어간 위시 목록(각 `Checkbox`, 체크 해제 = 이번 달에서 빼기), 부족분 넘김 안내 "32,000원이 11월로 넘어가요", `[확인]`.
- 결제수단: 카드(카드 목록과 연결), 계좌, 현금, 간편결제(카카오페이 등 — 연결 카드 지정 가능 [제안]). 삭제(해지 카드 — 휴지통으로, D-075).

### 7.0 기록 영역 공통 (SCR-REC-01)

- 상단 `Tabs`: `일기` · `작품` · `위시` · `건강`. 마지막으로 연 탭을 기억한다. [제안]

### 7.1 일기 목록 (SCR-JRN-01) [확정: 일기·사진·한 날짜 여러 주제]

**목적**: 기록한 날을 훑어보고 지난 글을 찾는다.

**보기**: `Toggle Group` `목록` / `달력`.

```
│ ┌ 회고 ─────────────── ▢▢ ┐ │  ← 주제 배지 · 제목(또는 첫 줄) · 사진 썸네일 최대 2
│ │ 이번 주는 생각보다…            │ │
│ └──────────────────────┘ │
```

- 주제 필터: `Select`(PC) / 칩(모바일).
- 빈 상태: "오늘 있었던 일을 남겨 보세요" `[오늘 기록 쓰기]`.

### 7.2 날짜별 글 모음 (SCR-JRN-02)

- 머리: 날짜, `[+ 이 날 글 추가]`.
- 그 날짜의 글을 주제별로 이어서 보여 준다(글마다 카드: 주제 배지, 제목, 본문 전체, 사진 격자, `···` 수정·삭제).
- 같은 날 다른 기록 요약(접힘 `Collapsible` "이 날의 다른 기록"): 지출 합계, 트래커 완료, 본 작품. [제안] — 일기를 쓰며 하루를 돌아보기 좋도록.

### 7.3 일기 작성·수정 (SCR-JRN-03)

**그릇**: 모바일·PC 모두 **전체 화면 에디터**(PC는 가운데 720px). 긴 글·사진이라 Dialog·Drawer를 쓰지 않는다. [03 §4.1]

```
┌─────────────────────────────────┐
│ [←]  11월 1일 (일) ▾        [저장]  │
│ 주제  [일상][회고][감사][여행][+]     │  ← 하나 선택(필수), 새 주제 추가
│ 제목 (선택)                         │
│ ─────────────────────────────── │
│ 본문…                               │
│                                   │
│ ▢ ▢ ▢ [+ 사진]                      │  ← 사진 순서 드래그, 탭하면 크게(Lightbox)
├─────────────────────────────────┤
│ 📷  B  I  •  "               자동 저장됨 │  ← 모바일: 키보드 위 도구 막대
└─────────────────────────────────┘
```

| 요소 | 컴포넌트 | 비고 |
|---|---|---|
| 날짜 | 버튼 → `Calendar` Popover/Drawer | 기본 오늘. 지난 날짜 가능 |
| 주제 | `Toggle Group`(single) 칩 + `+` → 새 주제 Popover | [확정: 여러 주제] 한 글 = 주제 1개 [제안] |
| 제목 | `Input`(borderless) | 선택 |
| 본문 | 리치 텍스트 에디터(굵게, 기울임, 목록, 인용, 체크 목록) [미결정 Q-070: 에디터 라이브러리] | 마크다운 저장 [제안] |
| 사진 | `UploadDropzone` + 썸네일 격자 | 최대 10장, 자동 리사이즈, 업로드 진행률 |
| 자동 저장 표시 | 작은 글자 | 기기 임시 저장 5초마다, 서버 저장은 `저장` 시 |

- 뒤로 가기·닫기 시 저장하지 않은 변경이 있으면 `Alert Dialog` "작성 중인 글을 저장하지 않고 나갈까요?" `[계속 쓰기]` `[저장하지 않고 나가기]`(+ 임시 저장은 기기에 남아 다음에 "작성 중인 글이 있어요"로 복원).
- 사진 업로드 중 저장: 업로드가 끝날 때까지 저장 버튼에 Spinner, "사진 2장 올리는 중".
- 사진 업로드 실패: 썸네일에 오류 표시 + 탭하면 `다시 시도`/`빼기`.

### 7.4 작품 (독서·영화·드라마) (SCR-MED-01) [확정: 기간·상태·감상·표지·포스터 캘린더]

**보기**: `Toggle Group` `캘린더` / `목록`. 종류 필터 `Toggle Group` `전체` `책` `영화` `드라마`.

**포스터 캘린더**

```
PC
┌─────────────────────────────────────────────────────────┐
│ [<] 2026년 11월 [>]   (캘린더|목록)  (전체|책|영화|드라마)  [+ 추가] │
├──────┬──────┬──────┬──────┬──────┬──────┬──────┤
│  1   │  2   │  3   │  4   │  5   │  6   │  7   │
│┌──┐  │      │┌──┐┌─│      │      │      │      │
││▢▢│  │      ││▢▢││ │      │      │      │      │  ← 그 날 완독/관람한 작품 포스터(2:3)
││▢▢│  │      ││▢▢│+1│      │      │      │      │     여러 개면 겹쳐 쌓고 +n
│└──┘  │      │└──┘  │      │      │      │      │

모바일: 월 격자 칸이 작아(약 48×72px) 포스터 1장 + 숫자 배지. 날짜 탭 → 아래 목록에 그 날 작품.
```

- 캘린더에 놓이는 날짜 [제안]: 책 = 다 읽은 날(완독·중도 포기 날), 영화 = 본 날, 드라마 = 다 본 날(보는 중이면 시작일에 흐린 표시). 설정 `시작한 날에도 표시`로 바꿀 수 있음.
- 읽는 중인 책: 캘린더 상단 띠 "읽는 중 2" (탭하면 목록).
- 포스터 호버(PC): `Hover Card`(제목, 별점, 기간, 감상 첫 줄). 탭·클릭: 상세.
- 표지가 없는 작품: 종류 아이콘 + 제목 글자로 만든 기본 표지(테마 `secondary` 배경). [제안]

**목록 보기**: 상태 그룹(`읽는 중·보는 중` / `다 봄` / `중도 포기`), 행 = 썸네일 · 제목 · 저자/감독 · 기간 · 별점.

### 7.6 위시 (SCR-WISH-01) [확정: 작품 위시 + 쇼핑, 쇼핑은 Like/Want/Need 구분, 링크·이미지·텍스트]

**상단**: `Toggle Group` `쇼핑` / `작품`.

**쇼핑 구분 라벨** [확정: 3구분, 화면 라벨 D-045]

| 내부 코드 | 화면 라벨 | 아이콘 | i 설명(판단 기준) |
|---|---|---|---|
| `like` | 관심 | `eye` | 눈여겨보는 중이에요. 당장 살 생각은 없어요. |
| `want` | 갖고 싶음 | `heart` | 사고 싶지만 없어도 생활에 지장은 없어요. |
| `need` | 필요 | `circle-alert` 또는 `check-check` | 생활이나 일에 꼭 필요해서 사야 해요. |

- 화면에는 영어 코드를 절대 노출하지 않는다. [확정 원칙]
- i는 구분 필터 옆 하나만 둔다(항목마다 붙이지 않음).

**쇼핑 레이아웃**

```
PC (이미지 카드 격자 3~4열)
┌───────────────────────────────────────────────────────────┐
│ (쇼핑|작품)  (전체|필요|갖고 싶음|관심) ⓘ   정렬[담은 날▾]  [+ 담기] │
├──────────────┬──────────────┬──────────────┬──────────────┤
│ ▢▢▢▢▢▢▢▢▢▢ │ ▢▢▢▢▢▢▢▢▢▢ │              │              │  ← 이미지 1:1
│ 필요           │ 갖고 싶음       │              │              │  ← 구분 배지
│ 무선 청소기     │ 가죽 가방       │              │              │
│ 289,000원     │ 159,000원     │              │              │
│ 12일째 🔗      │ 30일째 🔗      │              │              │  ← 담아둔 기간, 링크 있음
└──────────────┴──────────────┴──────────────┴──────────────┘
▸ 구매함 5   ▸ 그만둠 2   (Collapsible)

모바일: 2열 격자(이미지 위주) 또는 목록 보기(설정). 상단 구분 칩 가로 스크롤.
```

- 정렬: 담은 날(기본, 최신), 오래 담아둔 순, 가격, 구분(필요 → 갖고 싶음 → 관심).
- 카드 탭 → 상세(PC Sheet / 모바일 전체 화면).
- **구매 체크** [확정]: 카드 오른쪽 위 원형 체크 버튼(44px 터치 영역, 접근성 이름 "구매했어요", PC Tooltip). 누르면 구매 처리(§7.8)가 열린다. 상세에 들어가지 않고 목록에서 바로 체크한다.
- 가격은 카드에 항상 보인다(A 등급) [확정: 가격 필요]. 가격이 비어 있는 예전 항목은 가격 자리에 "가격 없음" `warning-text` + 탭하면 가격 입력 Popover.
- 참은 소비 표시: 참은 소비로 기록된 위시는 카드 아래 작은 글 "10월에 참음". 이번 달 말 자동 포함 후보는 "이번 달에 안 사면 참은 소비로 들어가요"(갖고 싶음·관심만, 설정으로 끄기). [20 §4.2]
- 구분 빠른 변경: 카드 `···` → 구분 바꾸기(하위 메뉴 3개) / 모바일 길게 누르기.

**작품 위시**: 목록(포스터 썸네일 · 제목 · 종류 · 메모). 행마다 버튼 두 개 [확정: 완료 처리 후 후기로] [제안: 형태]:
- 완료 버튼(outline, 행 오른쪽 상시 노출): 책 `다 읽었어요` / 영화 `봤어요` / 드라마 `다 봤어요` → 작품 기록 폼이 완료 상태·오늘 날짜·위시 정보로 채워진 채 열리고 **감상 칸에 바로 포커스**. 저장하면 위시는 "다 봄" 묶음(접힘)으로, 작품은 작품 기록·포스터 캘린더로 들어간다. 토스트 "작품 기록으로 옮겼어요 · 감상 보기".
- `···`: `읽기 시작`/`보기 시작`(진행 중으로 옮기기, 위시는 "시작함" 묶음), 수정, 삭제.
- 모바일은 완료 버튼을 행 오른쪽 아이콘 버튼(`check`, 접근성 이름 "다 봤어요")으로 줄이고, 길게 누르면 메뉴.

### 7.7 위시 상세·담기 (SCR-WISH-02, 03)

**담기 폼** (`ResponsiveModal`; 모바일은 Drawer → 사진이 있으면 전체 높이)

| 필드 | 컴포넌트 | 필수 | 비고 |
|---|---|---|---|
| 링크 | `Input Group`(🔗 아이콘, 붙여넣기 버튼) | 선택 | 붙여넣으면 미리보기 가져오기 시도 → 이름·이미지·가격 자동 채움(가능한 경우) [검증 필요: 인스타그램 등은 미리보기 실패 가능] |
| 이름 | `Input` | 필수 | |
| 구분 | `Toggle Group` 3개 + ⓘ | 필수 | 기본 `관심` |
| 이미지 | `UploadDropzone`(여러 장) + 미리보기로 가져온 이미지 | 선택 | 스크린샷 업로드가 흔할 것(릴스 캡처) |
| 가격 | `AmountInput` | **필수** | HintText "대략적인 금액도 괜찮아요". 미리보기로 찾으면 자동 채움 [확정: 가격 필요] |

| 링크 추가 | `[+ 링크 추가]` | 선택 | 여러 링크(판매처 비교) |

- 미리보기 실패: 링크 칸 아래 HintText "미리보기를 가져오지 못했어요. 이름과 사진을 직접 넣어 주세요." (오류 색 아님)

**상세**

| 영역 | 내용 |
|---|---|
| 이미지 | `Carousel`(여러 장), 탭 → Lightbox |
| 머리 | 이름, 구분 배지(탭하면 바꾸기 Popover), 가격 |
| 담은 날 | "10월 2일에 담음 · 30일째" |
| 어디서 봤는지 | 본문 |
| 링크 | 링크 목록(도메인 + 열기 아이콘). 외부 링크는 새 탭 |
| 작업 | `[구매함]`(default), `···`(수정, 그만둠, 삭제) |

### 7.8 구매 처리 (SCR-WISH-04) [제안: 위시 → 지출 연결]

```
[구매함] 탭
  → 지출 입력 Drawer/Dialog(SCR-FIN-03)가 열림
     - 금액 = 위시 가격(수정 가능), 내용 = 위시 이름, 분류 = 쇼핑(기본), 날짜 = 오늘
     - 상단 출처 칩 "위시: 무선 청소기"
  → [지출 추가] 저장
     → 위시 상태 = 구매함, 지출과 연결
     → 토스트 "구매함으로 옮겼어요 · 되돌리기"
  → 지출 입력에서 [지출 없이 구매함으로] (link): 지출 기록 없이 상태만 변경(선물 받음 등)
```

- `그만둠`: 상태 변경(사지 않기로 함). "그만둠" 묶음으로 이동. Popover: 이유 한 줄(선택) + `참은 소비로 기록하기` Checkbox(기본 켬, "159,000원이 이번 달 참은 금액에 더해져요"). [20 §4.1]
- 참은 소비로 기록된 위시를 구매할 때: 구매 처리 시트 상단 InlineNotice "10월에 참은 물건이에요. 사면 이번 달 참아야 할 금액에 159,000원이 더해져요." [20 §5.3]
- 연결된 지출을 삭제하면 위시는 구매함 상태 유지 + 상세에 "연결된 지출이 삭제됐어요".

### 7.9 건강 (SCR-HLT-01) [확정: 생리주기, 체중, 혈당 날짜별 기록]

**목적**: 건강 기록을 빠르게 남기고 추세를 본다. 민감 정보이므로 노출을 최소화한다. [제안]

**레이아웃**

```
┌───────────────────────────────────────┐
│ 건강                       🔒  [+ 기록]  │  ← 🔒: 잠금 설정됨 표시, 탭하면 지금 잠그기
├───────────────────────────────────────┤
│ 생리주기                             >  │
│ 다음 예정일 11월 18일 · 17일 남음 ⓘ       │
│ [오늘 시작]                             │  ← 생리 중이면 [오늘 끝남]
├───────────────────────────────────────┤
│ 체중                                 >  │
│ 52.3kg  어제 · 지난주보다 -0.4kg          │
│ (작은 선 그래프 30일)                     │
├───────────────────────────────────────┤
│ 혈당                                 >  │
│ 오늘 공복 98mg/dL · 식후 2시간 132mg/dL   │
│ (작은 점 그래프 14일)                     │
└───────────────────────────────────────┘
PC: 2열 카드. 모바일: 1열.
```

- ⓘ(예정일): "최근 6번의 주기 평균으로 계산해요. 실제와 다를 수 있어요."
- 기록이 2회 미만이면 예정일 자리에 "주기를 두 번 이상 기록하면 예정일을 알려 드려요".
- 혈당 정상 범위 표시는 사용자가 설정한 목표 범위만 띠로 표시(의학적 판정 문구 없음). [제안]
- `[+ 기록]` → 종류 선택(체중/혈당/생리/직접 만든 지표) → 입력 Drawer.

### 7.10 건강 기록 입력·추세·잠금 (SCR-HLT-02, 03)

**입력** (모바일 Drawer / PC Popover 또는 Dialog sm)

| 종류 | 필드 |
|---|---|
| 체중 | 날짜(기본 오늘), 값 `Input`(kg, 소수 1자리, inputmode decimal), 메모 |
| 혈당 | 날짜·시간(기본 지금), 측정 시점 `Toggle Group`(공복/식전/식후 1시간/식후 2시간/취침 전/기타), 값(mg/dL), 메모 |
| 생리 | 시작일/종료일(달력 범위), 양(선택: 적음/보통/많음), 증상 칩(선택), 메모 |
| 직접 만든 지표 | 이름·단위는 지표 설정에서, 입력은 값·날짜·메모 (P2) |

- 같은 날 체중을 다시 입력하면 "오늘 기록을 바꿀까요?" 대신 그대로 추가하고 그 날 마지막 값을 대표값으로 쓴다(하루 여러 번 허용). [제안]

**추세 화면** (지표별): 기간 `Toggle Group`(1주/1달/3달/1년), 선 차트 + 표 대체 보기(`Tabs` 차트/표), 기록 목록(수정·삭제).

**잠금** [제안]
- 설정 > 개인정보 > `건강 기록 잠금`(Switch). 잠금 방식 [미결정 Q-042]: 기기 생체 인증(패스키) 또는 앱 PIN 4~6자리.
- 잠긴 상태: 건강 탭 내용 대신 자물쇠 + "잠금을 풀어야 볼 수 있어요" `[잠금 해제]`. 해제 후 앱을 벗어나거나 5분이 지나면 다시 잠김.
- 잠금이 켜져 있으면 건강 홈 위젯·검색 결과·캘린더 겹쳐 보기에도 나타나지 않는다.

### 8.3 AI 비서 (SCR-SET-03) → [12](12-ai-assistant.md)

| 섹션 | 내용 | 컴포넌트 |
|---|---|---|
| 연결 | 제공자별 행(ChatGPT·Claude·Gemini): 연결 상태, 연결 방법 표시, `[연결]`/`[관리]` | `Item` |
| 기본 AI | 대화에 쓸 제공자·모델 | `Select` |
| 데이터 접근 | 영역별 `Switch`: 일정, 목표, 지출·예산, 카드 혜택, 기록(일기·작품), 위시, **건강(기본 끔)** + 영역별 i | `Switch` |
| 확인 | "기록을 추가하기 전에 항상 물어보기"(기본 켬, 끌 수 없음 [제안]) | 설명 텍스트 |
| 사용량 | 이번 달 요청 수·토큰(P2) | |
| 대화 기록 | 보관 기간 `Select`(30일/90일/계속), `대화 기록 모두 지우기` | Alert Dialog |

**연결 Dialog (제공자 선택 후)**
- 상단: 연결 방식 `Radio Group` — `API 키`(기본, 모든 제공자) / `ChatGPT 계정으로 로그인`(OpenAI만, [검증 필요]) / `내 컴퓨터의 AI 도구 사용`(1단계 본인 전용, [검증 필요]). 각 한 줄 설명. 검증되지 않은 방식은 기본 숨김 또는 "실험 기능" 배지. [검증 반영: 19 §4]
- API 키: `Input`(password 형태, 붙여넣기), ⓘ "API 키는 ChatGPT·Claude·Gemini 웹 구독과 별도로 각 회사 개발자 사이트에서 발급하고, 사용한 만큼 비용이 나와요." + `? 키 발급 방법`(가이드, 제공자별 탭).
- `[연결 테스트]` → 성공: "연결됐어요" + 사용 가능한 모델 목록 → `[저장]`. 실패: 필드 아래 원인별 문구("키가 맞지 않아요", "결제 정보가 등록되지 않았어요", "요청 한도를 넘었어요").
- 저장 후 키는 끝 4자리만 표시 `sk-…a1B2`. 다시 볼 수 없음, 바꾸기만 가능.

### 8.4 알림 (SCR-SET-04)

- 전체: 앱 알림 받기(웹 푸시 권한 요청 버튼 — iOS는 홈 화면에 추가한 뒤에만 가능하다는 안내 [검증 반영]), 펫 말풍선으로 알리기, 방해 금지 시간(시작·끝 시각).
- 종류별 `Switch` + 시점 `Select`: 일정(기본 30분 전), 결제 예정(1일 전), 해지 예정(3일 전), 목표 체크 누락(오후 9시, 기본 끔), 예산 주의(80%), 카드 실적(월말 7일 전), 자산 업데이트(매월 1일, 기본 끔), 건강(생리 예정 3일 전, 기본 끔).
- 권한이 거부된 경우: InlineNotice "브라우저에서 알림이 꺼져 있어요" + 기기별 켜는 방법 `?`.

### 8.5 화면 (SCR-SET-07)

테마(`Radio Group`: 시스템/밝게/어둡게, 미리보기 썸네일), 주 시작 요일, 시간 표시(12/24시간), 트래커 완료 표시 아이콘, 고정 지출 메모 미리보기, 안내 다시 보기(최초 안내 초기화), 움직임 줄이기(시스템 따름/항상).

### 8.6 개인정보·보호 (SCR-SET-08)

건강 기록 잠금, 잠금 방식, 홈·캘린더·검색에서 건강 기록 숨기기, AI 데이터 접근(→ 8.3 바로가기), 내 데이터 내보내기, 완전 삭제 요청.

### 8.7 휴지통 (SCR-SET-09) [확정: soft delete] [제안: 화면]

| 요소 | 내용 |
|---|---|
| 필터 | 영역 `Select`(전체, 일정, 목표, 지출, 고정 지출, 카드, 일기, 작품, 위시, 건강, 펫) |
| 목록 | PC `Data Table`(선택 체크 · 종류 아이콘 · 이름 · 삭제한 날 · `[복구]`) / 모바일 `Item`(왼쪽 스와이프 `영구 삭제`, 탭 `복구` 메뉴) |
| 일괄 | 선택 후 `복구`, `영구 삭제` |
| 비우기 | `휴지통 비우기`(link, 하단) |
| 보존 안내 | 상단 한 줄 "휴지통 항목은 90일 뒤 자동으로 영구 삭제돼요" [확정 D-048]. 각 행에 남은 날 "12일 남음"(7일 이하면 warning) |

- 복구: 원래 위치로, 연결 관계도 복원(트래커 항목 → 칸 기록 함께). 원래 부모가 삭제돼 있으면 함께 복구할지 묻는 Dialog.
- 영구 삭제: `Alert Dialog` "영구 삭제할까요?" "삭제하면 되돌릴 수 없어요. 변경 기록도 함께 지워져요." `[취소] [영구 삭제]`.
- 건강 기록은 잠금 해제 상태에서만 보인다.

### 8.8 변경 기록 (항목별, SCR-HIST)

- 진입: 각 항목 상세의 `변경 기록` 링크. 별도 메뉴 없음.
- PC `Sheet` / 모바일 전체 화면. 타임라인: 시각 · 변경 종류(만듦/고침/휴지통으로/복구) · 바뀐 필드 "금액 12,000원 → 13,000원".
- 각 시점 `이 상태로 되돌리기`(Alert Dialog 불필요: 되돌리기도 새 변경으로 기록). [제안]
- 내부 필드명은 화면 라벨로 바꿔 표시(`amount` → 금액).

### 8.9 보안 기록 (SCR-SET-10)

로그인 기록(시각, 방법, 기기, 대략 위치 없음 [제안: 위치 수집 안 함]), 비밀번호·로그인 연결 변경, 내보내기, 영구 삭제, AI 데이터 조회 기록(어떤 영역을 언제 조회했는지). PC 표 + 페이지 이동, 모바일 목록.

### 8.10 내보내기 (SCR-SET-11)

- 영역 선택 `Checkbox`(기본 전체, 건강은 기본 해제), 형식 `Radio Group`(JSON 전체 / CSV 표 데이터), `사진·첨부 포함` `Switch`.
- `[내보내기 시작]` → 서버에서 파일 생성(진행 표시, 화면을 떠나도 됨) → 완료 알림 → 내려받기 링크(24시간 유효).

### 8.11 탈퇴·완전 삭제 (SCR-SET-12) [확정: 개인정보 완전 삭제 요청은 soft delete 예외]

1. 안내: 삭제되는 것(모든 기록·사진·펫·연결 정보), 유예 기간(14일 [제안]), 유예 중 로그인하면 취소 가능, 백업에서도 보관 기간이 지나면 사라짐.
2. `내보내기 먼저 하기` 링크.
3. 본인 확인: 비밀번호 또는 간편 로그인 재인증.
4. 확인 입력: "탈퇴" 입력(`Input`) 후 `[탈퇴 신청]`(destructive, Alert Dialog로 한 번 더).
5. 완료 화면: "14일 뒤 모든 데이터가 삭제돼요" + 취소 방법.

| 위치 | 화면 아래쪽 바닥선(하단 64px 띠)을 주 활동 영역, 커서를 따라올 때만 화면 안쪽 | 하단 탭 바로 위 띠, 빠른 추가 버튼 영역(오른쪽 아래 88×88px) 제외 |
| 크기 | 기본 72px(설정 50~120%) | 기본 56px |
| 반응 | 호버: 애교 / 클릭: 놀람 + 대화창 / 커서 이동: 따라옴 / 무동작: 갸웃·쳐다봄 [확정] | 탭: 놀람 + 대화창 / 길게 누르기: 펫 메뉴 / 끌기: 옮기기 / 무동작: 갸웃·잠 |
| 안전 영역 | 입력 중인 필드, 열린 Popover·Dialog·Sheet·Drawer, 버튼 위에 멈추지 않음. 겹치면 옆으로 비켜 감 | 동일 + 키보드 열리면 숨김 |
| 말풍선 | 펫 위쪽 `PetBubble`(최대 2줄, 4초 표시 후 접힘, 탭하면 관련 화면) | 동일 |
| 숨기기 | 펫 메뉴 `잠깐 숨기기`(1시간/오늘/계속) | 동일 |

- 접근성: 펫 자체는 장식(`aria-hidden`), 말풍선 내용은 알림 센터 + 화면 낭독기용 라이브 영역.
- 펫 메뉴(PC 우클릭 / 모바일 길게 누르기): `대화하기`, `꾸미기`, `펫 바꾸기`, `잠깐 숨기기`, `펫 설정`. `DropdownMenu`(PC) / `Drawer`(모바일).

### 9.3 펫 관리 (SCR-SET-05) [확정: 프리셋 + 사용자 지정 펫, 여러 펫 중 고르기는 제안]

```
┌──────────────────────────────────────────────┐
│ 오늘의 펫                                       │
│ [▢ 판다 ✔] [▢ 곰] [▢ 병아리] [▢ 강아지] [▢ 백호]    │  ← 기본 펫 5종
│ 내 펫 🔒                                        │
│ [▢ 우사기] [▢ 하치와레] [+ 새 펫 추가]              │  ← 사용자 지정 펫(나만 보여요)
├──────────────────────────────────────────────┤
│ 펫 보이기  (Switch)                              │
│ 움직임 · 크기 · 알림 → 꾸미기                        │
```

- 펫 카드: 대기 애니메이션 미리보기(호버 시 재생, 움직임 줄이기 시 정지 이미지), 이름, 선택 표시. 탭하면 오늘의 펫으로 변경.

**그릇**: PC `Dialog md`(가이드를 열면 오른쪽에 `Sheet`로 나란히) / 모바일 전체 화면(가이드는 별도 전체 화면, 돌아오면 입력 유지).

```
│ 새 펫 추가                         ? 가이드  │
│                                          │
│ 이름  [                    ]              │
│                                          │
│ 유형                                      │
│ (●) 기본형        이미지 한 장으로 간단하게     │
```

**정보 배치** [ChatGPT 대화 제안 표 반영]

| 정보 | 표시 |
|---|---|
| 펫 이름 | 입력 필드 |

| 등록 후 실제 모습 | 미리보기(모달 하단, 실제 펫 레이어와 같은 렌더러) |

- "PNG·WebP·GIF 파일만 올릴 수 있어요"

- "가만히 있기 동작이 필요해요" (애니메이션형 저장 시)
- ZIP: "동작 묶음에서 pet.json을 찾지 못했어요. 가이드의 폴더 구조를 확인해 주세요" + `가이드 열기`

**비공개 표시**: 저장 버튼 위 작은 글자 "내 계정에서만 보여요" + `lock`. [확정]

### 9.5 펫 만들기 가이드 (SCR-HELP-PET) [제안: ChatGPT 제안 구성]

`GuideDialog` lg / 모바일 전체 화면. 목차 `Tabs`(PC 왼쪽 세로 탭, 모바일 상단 가로 스크롤 탭):

1. **시작하기** — 기본형과 애니메이션형 차이(그림 2개)
2. **파일 형식** — 지원 형식, 권장 크기, 투명 배경, 용량
3. **동작 목록** — 동작별 이름·필수 여부·없을 때 대체 동작 표([11 §5](11-pet-system.md))
4. **움직이는 파일 만들기** — 프레임 수·속도 권장, 반복 재생, 정면·측면 통일 팁
5. **동작 묶음(ZIP)** — 폴더 구조 예시, pet.json 예시
6. **미리보기·문제 해결** — 자주 나는 오류와 해결
7. **샘플 내려받기** — 기본형 샘플 PNG, 애니메이션형 샘플 ZIP `[샘플 내려받기]`

- 가이드를 연 채로 업로드 모달의 입력이 유지된다(PC 나란히 보기). [확정 원칙: 읽으면서 업로드할 수 있는 구조]

## 10. AI 대화

상세 동작은 [12 AI 비서](12-ai-assistant.md).

### 10.1 미니 대화창 (SCR-AI-MINI) [확정: 펫과 대화] [제안: 형태]

| 항목 | PC | 모바일 |
|---|---|---|
| 그릇 | 펫 위쪽에 떠 있는 패널 360×520px(`Card` + `shadow-xl`), 화면 밖으로 넘치면 위치 조정 | `Drawer`(높이 70vh, 위로 끌면 전체 화면) |
| 머리 | 펫 얼굴 아바타 + 이름 + 상태("생각하는 중…") + `확장`(전체 대화) + 닫기 | 동일 |
| 본문 | 메시지 목록(최근 대화 이어짐) | 동일 |
| 입력 | `Textarea`(자동 높이, Enter 전송 / Shift+Enter 줄바꿈) + 전송 버튼 | 전송 버튼, 키보드 위 고정 |

- 열릴 때 펫은 놀람 애니메이션 후 말하기 대기 동작. AI 응답 중엔 생각하기 동작. [확정: 상태별 반응]

### 10.2 메시지 구성

| 메시지 요소 | 컴포넌트 | 설명 |
|---|---|---|
| 텍스트 답변 | 마크다운 렌더(굵게·목록·표 정도만) | 스트리밍 표시 |
| 선택지 질문 | `ChoiceChips` | [확정] 추가 질문의 선택지는 클릭으로. 단일 선택은 누르는 즉시 전송, 복수 선택은 `확인`. 항상 마지막에 `직접 입력` |
| 근거 | `Collapsible` "근거 보기": 조회한 데이터 요약("11월 지출 32건 · 식비 분류"), 각 항목 링크 | 답이 내 데이터에 기반했음을 확인 |
| 작업 제안 | `ConfirmCard`: "이렇게 기록할까요? 지출 12,000원 · 식비 · 오늘" `[저장]` `[수정]` `[취소]` | 저장 전 반드시 확인 [제안] |
| 권한 요청 | `Alert` 카드: "지출 기록을 보려면 허용이 필요해요" `[이번만 허용]` `[항상 허용]` `[허용 안 함]` | 영역 접근이 꺼져 있을 때 |
| 오류 | 메시지 자리 InlineNotice + `다시 시도` | 원인별 문구(§10.4) |

**선택지 예시 (카드 추천)**

```
나:  CGV 결제할 건데 어떤 카드가 좋아?
펫:  몇 명이 보시나요?

나:  (2명 탭)
펫:  A카드가 가장 유리해요. 영화 4,000원 할인을 1회 더 받을 수 있어요.
     B카드는 이번 달 할인 한도를 이미 다 썼어요.
     ▸ 근거 보기
```

### 10.3 전체 대화 화면 (SCR-AI-FULL, /assistant)

```
기록 > 위시 > 작품 → "파묘" 행 [봤어요] → 작품 기록 폼(봤어요·오늘·포스터 채워짐, 감상 칸 포커스)
→ 별점·한 줄 평·감상 → [기록 저장] → 포스터 캘린더 오늘 칸에 포스터
```

### 12.5 카드 추천 (AI 미연결 / 연결)

```
미연결: 자산 > 카드 > [어떤 카드 쓸까?] → "CGV" 28,000원 → [비교하기] → 순위

        (내부적으로 같은 계산 기능을 도구로 호출)
```

### 12.6 사용자 지정 펫 등록

```
설정 > 펫 → [+ 새 펫 추가] → 이름 "우사기" → 유형 애니메이션형 → ⓘ로 권장 크기 확인
→ ? 가이드(오른쪽 Sheet)에서 동작 목록 보며 파일 올리기: 가만히 있기 ✔, 걷기 ✔, 놀라기 ✔

```
