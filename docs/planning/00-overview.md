## 0. 이 문서 묶음을 읽는 법

모든 기획 문서는 아래 네 가지 표식으로 각 항목의 확정 수준을 구분한다. 표식이 없는 문장은 해당 절의 표식을 따른다.

| 표식 | 의미 | 개발 시 취급 |
|---|---|---|
| **[확정]** | 사용자가 직접 요청하거나 결정한 사항 | 그대로 구현한다. 바꾸려면 사용자 승인이 필요하다. |
| **[제안]** | AI(ChatGPT 대화 또는 이 문서 작성자)가 제안했고 사용자가 아직 승인하지 않은 사항 | 기본안으로 진행하되, 구현 전 [18 결정 기록](18-decisions-and-open-questions.md)에서 확인한다. |
| **[검증 필요]** | 기술·비용·약관 검증 전에는 확정할 수 없는 사항 | 프로토타입이나 조사로 검증한 뒤 확정한다. 검증 전에는 대체 경로를 함께 설계한다. |
| **[미결정]** | 선택지만 있고 추천안도 확정되지 않은 사항 | 개발 착수 전 사용자 결정이 필요하다. |

또한 각 문서는 **화면에 보이는 정보**와 **내부 구현 정보**를 구분해 적는다.

- `화면 문구:` 로 시작하는 줄은 실제 UI에 노출되는 한국어 문구다.
- `내부:` 로 시작하는 줄, 데이터 필드명(영문 `snake_case`), 상태 코드 등은 사용자에게 절대 노출하지 않는다.
- 사용자가 기능을 요청한 이유나 개발 배경(예: "넷플릭스 이중 결제를 막으려고")은 기획 근거로만 적고 UI 문구에 넣지 않는다.

## 1. 제품 한 줄 정의

**나의 하루와 목표, 돈, 기록, 건강을 한곳에서 관리하고, 서로 연결된 데이터로 더 나은 결정을 돕는 개인용 일상 관리 웹앱.** [확정: 범위] [제안: 문장]

- 가칭(내부): `my-life-manager` [확정: 프로젝트 폴더명]
- 서비스 이름(화면 표시명): **우나** · 영문 **oona** [확정 D-051]. "우리의 나날들"을 줄인 이름.

| 쓰는 곳 | 값 [제안] |
|---|---|
| 앱 이름(설치 시 홈 화면 아이콘 아래) | 우나 |
| 매니페스트 `name` / `short_name` | 우나 / 우나 |
| 영문 표기(로고 보조, 파일·폴더 이름) | oona |
| 로그인·온보딩 화면 | 로고 "우나" + 작은 글 "우리의 나날들" |
| 본인 PC의 Tailscale 기기 이름 | `oona` → 접속 주소 `https://oona.<tailnet>.ts.net` (한 번 정하면 바꾸지 않음, 16 §5.3) |
| 프로젝트 폴더·저장소 이름 | `my-life-manager` 유지(내부 이름, 화면에 노출 안 함) |
| 로고·아이콘 | [확정 D-058] 사용자 로고(`assets/logo.png`) |

## 2. 배경과 문제

| 현재 문제 | 원하는 상태 |
|---|---|
| 가계부, 캘린더, 일기, 습관 트래커, 독서 앱이 따로 있어서 기록이 흩어진다. | 하나의 앱에서 모든 일상 기록을 남긴다. [확정] |
| 앱마다 정보가 많아 화면이 복잡하다. | 정보 위계를 따져 꼭 필요한 정보만 보이고 나머지는 접거나 모달·도움말로 뺀다. [확정] |
| 구독·고정 지출의 포함 혜택(예: 멤버십에 포함된 OTT)을 잊어 중복 결제한다. | 고정 지출마다 메모를 남기고 바로 확인한다. [확정] |
| 카드가 여러 장이라 어떤 카드를 써야 혜택이 큰지 매번 헷갈린다. | 카드 혜택을 저장하고, 지출 기록 기반 분석과 챗봇 상담을 받는다. [확정] |
| SNS 광고나 릴스를 보고 담은 물건이 왜 담았는지 기억나지 않는다. | 위시 항목에 링크·이미지·메모를 남긴다. [확정] |
| 모바일과 PC를 둘 다 자주 쓴다. | 각 화면 크기에 맞게 최적화된 반응형 웹앱. [확정] |

## 3. 핵심 가치 [제안]

1. **한곳에 모으기** — 일정, 목표, 돈, 기록, 건강을 한 계정에 모은다.
2. **연결하기, 중복 입력 없이** — 위시리스트에서 구매하면 지출이 미리 채워지고, 독서 기록이 독서 목표 진행률로 이어진다.
3. **보이는 건 적게, 필요한 건 바로** — 첫 화면은 요약, 상세는 필요할 때. 설명은 i·?·가이드로 분리한다.
4. **잃어버리지 않는 데이터** — 삭제는 기본적으로 soft delete, 모든 변경은 이력으로 남고 복구할 수 있다. [확정: soft delete·변경 이력]
5. **친근한 동반자** — 화면을 돌아다니는 펫이 알림을 전하고 AI 비서의 얼굴이 된다. [확정: 펫·대화]

## 4. 대상 사용자

| 단계 | 사용자 | 특징 |
|---|---|---|
| 1단계 | 본인 1명 [확정] | 모바일·PC를 모두 자주 사용. 기획자 겸 사용자. 개인 AI 구독 보유. |
| 2단계 | 지인·소수 사용자 [확정: 확장 의도] [제안: 범위] | 초대 또는 공개 가입. 각자 AI API 키를 연결. |
| 3단계 | 공개 서비스 [제안] | 기본 펫·콘텐츠의 권리, 개인정보 처리방침, 운영 비용 검토 필요. |

설계 원칙: **처음부터 다중 사용자 데이터 격리를 전제로 만든다.** 1명이 쓰더라도 모든 데이터에 소유자(user)를 두고, 나중에 사용자를 늘릴 때 구조를 바꾸지 않는다. [제안]

## 6. 제품 형태 [확정]

- **웹앱을 앱 껍데기로 감싸 앱처럼 쓴다.** 업데이트는 웹 배포만으로 반영되어 번거롭지 않아야 한다. [확정]
  - 추천 구현: PWA(홈 화면 설치, 전체 화면 실행, 오프라인 셸). 필요 시 이후 Capacitor(모바일)·Tauri(PC) 래퍼 검토. [제안] → [16 아키텍처](16-architecture-and-operations.md)
- **운영**: 본인 PC에서 자가 운영한다. 휴대폰 등 바깥에서는 Tailscale 사설망으로 접속하며, 앱은 인터넷에 공개되지 않는다. [확정: D-034, D-043] → [16 §5](16-architecture-and-operations.md)
- **반응형**: 모바일과 PC를 각각 최적화한다. PC 화면을 줄인 것이 모바일이 아니다. [확정]
- **UI 기반**: shadcn/ui 컴포넌트를 상황에 맞게 골라 쓴다. [확정] → [03 디자인 시스템](03-design-system.md)

## 7. 대표 사용자 시나리오 [제안]

### S1. 아침 출근길 (모바일, 1분)
1. 홈 화면 아이콘으로 앱을 연다. 마지막 로그인 상태가 유지되어 바로 홈이 뜬다.
2. 홈 상단에서 오늘 일정 2건과 "오늘의 목표 3개 중 0개 완료"를 본다.
3. 어제 놓친 "영어 공부" 칸을 길게 눌러 어제 날짜로 체크한다.
4. 펫이 화면 가장자리에서 "오늘 넷플릭스 결제일이에요" 말풍선을 띄운다. 탭하면 고정 지출 상세가 열리고 메모 "네이버플러스 멤버십에 포함"이 보인다.

### S2. 점심 결제 직후 (모바일, 15초)
1. 하단 `+` 버튼 → `지출` 선택 → 하단 시트(Drawer)가 열린다.
2. 금액 키패드에 12,000 입력, 최근 사용 라벨 칩 중 `식비` 탭, 카드 칩 중 하나 탭, `저장`.
3. 토스트 "지출을 기록했어요 · 되돌리기"가 3초간 뜬다. 예산 초과가 되면 토스트 대신 예산 초과 금액이 함께 표시된다.

### S3. 영화 예매 전 카드 고르기 (PC 또는 모바일)
1. 펫을 클릭하면 작은 대화창이 열린다.
2. "CGV 결제할 건데 어떤 카드가 좋아?" 입력.
3. 비서가 "몇 명이 보시나요?" 와 함께 `1명` `2명` `3명 이상` 선택지 버튼을 띄운다. 사용자가 `2명`을 누른다.
4. 비서가 등록된 카드 혜택과 이번 달 실적·한도 사용량을 조회해 "A카드가 4,000원 할인으로 가장 유리해요. B카드는 이번 달 할인 한도를 이미 다 썼어요"라고 답한다. 근거 카드를 펼쳐볼 수 있다.

### S4. 주말 저녁 정리 (PC, 20분)
1. 왼쪽 사이드바에서 `목표` → `월간 트래커`. 한 달 전체가 한 화면에 보인다.
2. 셀을 클릭하면 색이 채워지고, 더블클릭하면 셀 안에 짧은 메모를 입력한다.
3. `기록` → `일기`에서 오늘 날짜에 "회고"와 "읽은 책" 두 주제를 각각 작성하고 사진 3장을 첨부한다.
4. `기록` → `작품`에서 다 읽은 책을 "완독"으로 바꾸고 별점과 감상을 쓴다. 독서 목표 "연간 24권" 진행률이 자동으로 1 올라간다.

### S5. 충동구매 점검 (모바일)
1. 인스타 릴스에서 본 가방 링크를 복사해 `기록` → `위시` → `추가`에 붙여넣는다. 링크 미리보기 이미지와 제목이 자동으로 채워진다(가능한 경우).
2. 구분을 `관심`으로 저장한다.
3. 2주 뒤 위시 목록에서 여전히 갖고 싶으면 `갖고 싶음`으로 올리고, 구매 시 `구매함`을 누르면 지출 입력 시트가 금액·이름이 채워진 채로 열린다.

### S6. 구독 해지 예약 (PC)
1. `자산` → `고정 지출`에서 넷플릭스 항목 `···` → `해지 예정`.
2. 마지막 이용일을 다음 달 15일로 지정한다.
3. 목록에서 항목에 "12월 15일 해지" 배지가 붙고, 다음 결제 예정 합계에서 12월 이후 금액이 빠진다. 해지일이 지나면 `해지됨` 묶음(접힘)으로 자동 이동한다.

### S7. 건강 기록 (모바일)
1. `기록` → `건강`(또는 홈 바로가기)에서 오늘 체중과 공복 혈당을 입력한다.
2. 생리 시작일을 탭 한 번으로 기록하면 다음 예상일이 갱신된다.
3. 건강 데이터는 AI가 기본적으로 읽지 못한다. 사용자가 설정에서 허용한 경우에만 대화에 활용한다.
