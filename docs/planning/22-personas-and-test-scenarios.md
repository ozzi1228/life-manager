# 22. 사용자 페르소나와 테스트 시나리오

> 사람마다 우나를 쓰는 방식이 달라서 생기는 문제를 미리 찾기 위한 문서. 페르소나 → 시나리오 → 경계값·극한값 순서.
> 각 시나리오는 **ID · 기기 · 순서 · 기대 결과**. 알려진 문제는 ⚠️로 표시.
> 기준: 2026-11-04 코드(입력 제한은 `src/server/*.ts` 스키마, 업로드는 `src/server/files.ts`·`src/lib/pet-convert.ts`).

## 0. 이번에 발견한 문제

### BUG-01 ✅ 일기를 삭제하면 404 화면이 뜸 (모바일에서 확인 · 2026-11-04 고침, db349e9)

- **재현**: 일기 목록 → 일기 하나 열기 → 삭제
- **실제**: 404(페이지 없음)
- **기대**: 그 달 일기 목록으로 돌아가고 "휴지통으로 옮겼어요 · 되돌리기" 알림
- **원인(추정)**: `entry-editor.tsx`의 `remove()`가 `router.push(목록)` 바로 다음에 `router.refresh()`를 부름. 이동이 끝나기 전에 refresh가 **지금 주소(이미 지운 일기 `/records/journal/[id]`)**를 다시 불러오고, 서버가 `notFound()`를 돌려줌. 일기가 하나뿐이었던 것과는 상관없이 삭제할 때마다 생길 수 있음
- **같은 패턴**: `career/experiences.tsx`의 경험 삭제(`router.push("/career")` → `router.refresh()`)
- **고칠 방향**: 삭제 후에는 `router.replace(목록)`만 하고 refresh는 하지 않음(목록 화면은 이동하면서 새로 불러옴). 되돌리기를 누른 뒤에만 refresh
- **회귀 테스트**: 아래 J-03, J-04, CR-04

### 글자 종류 (모든 글 입력칸)

- 이모지·결합 문자(👩‍👩‍👧, é를 e+´로) — 글자 수 세기가 화면과 서버가 같은지
- 앞뒤 공백만 있는 이름(서버가 trim → "입력해 주세요")
- 줄바꿈만 있는 본문, 5만 자 한 줄(줄바꿈 없음) — 가로 스크롤이 생기지 않는지
- `<script>`, 마크다운 링크 `[x](javascript:...)` — 그대로 글자로 보이거나 링크가 막히는지
- 오른쪽에서 왼쪽으로 쓰는 글자(아랍어) 섞기
