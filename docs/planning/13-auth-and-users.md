# 13. 계정·로그인·사용자

> 문서 상태: 초안 v0.1 · 작성일 2026-11-01
> 화면: [04 §2](04-screen-specifications.md#2-계정-화면), [04 §8.2](04-screen-specifications.md#82-계정-scr-set-02) · 데이터: [14 §4.1](14-data-model.md) · API: [15 §3](15-api-specifications.md) · 조사: [19 §3](19-integration-research.md#3-카카오-로그인--네이버-로그인)

## 1. 사용자 요구 [확정]

- 사용자는 본인 한 명으로 시작해서 확장한다.
- 일반 회원가입과 간편 로그인을 둘 다 지원한다.
- 일반 회원가입은 이메일을 아이디로 쓰지 않고 개인 아이디를 만든다.
- 간편 로그인은 카카오와 네이버만 지원한다.

## 2. 로그인 수단

| 수단 | 식별 | 비밀번호 | 비고 |
|---|---|---|---|
| 아이디 | 사용자가 만든 아이디 | 앱 비밀번호 | 이메일 선택 입력 |
| 카카오 | 카카오 회원번호(앱별) | 없음 | 닉네임·프로필 사진만 기본 동의. 이메일은 비즈 앱 필요 → 받지 않음 [제안] |
| 네이버 | 네이버 고유 식별자(앱별) | 없음 | 식별자 + 닉네임만 요청 [제안]. 가입 과정에서 앱 고유 비밀번호를 요구하면 검수 반려 → 요구하지 않음 [검증 반영] |

- 구글 인증은 캘린더 연결 전용이며 로그인 수단이 아니다. [07 §4.4]

## 3. 아이디 회원가입·로그인 [제안]

### 3.1 아이디 규칙
- 4~20자, 영문 소문자·숫자·`_`·`.`, 영문으로 시작, `.`·`_` 연속 금지.
- 대소문자 구분 없음(입력 시 소문자 변환).
- 예약어 차단: admin, root, system, support 등.
- 아이디는 변경 불가(로그·감사 추적 단순화). 변경 요구 시 [18 Q-130].
- 탈퇴한 아이디는 재사용 금지(완전 삭제 후에도 아이디 해시만 보관해 재가입 차단 — 개인정보 최소화와의 균형은 [18 Q-131]).

### 3.2 비밀번호
- 8~64자, 영문·숫자 포함, 흔한 비밀번호 목록(상위 10만 개) 차단, 아이디 포함 금지.
- 저장: Argon2id(메모리 19MiB 이상, 반복 2 이상 — OWASP 권장값 [검증 필요: 구현 시 최신 권장값]).
- 변경 시 현재 비밀번호 확인, 다른 기기 세션 로그아웃 선택.

### 3.3 로그인 보호
- 계정·IP별 실패 횟수 제한: 5회 실패 → 5분 지연, 이후 증가.
- 실패 메시지는 아이디·비밀번호 중 무엇이 틀렸는지 구분하지 않음.
- 새 기기 로그인 시 알림 센터에 기록(P1), 보안 기록에 남김.
- 2단계 인증(OTP·패스키) [제안] P2.

### 3.4 비밀번호 찾기 [미결정 Q-010]

| 사용자 | 추천 경로 |
|---|---|
| 이메일 등록함 | 이메일 재설정 링크(30분 유효, 1회용) |
| 이메일 없음 + 간편 로그인 연결됨 | 간편 로그인으로 본인 확인 → 새 비밀번호 설정 |
| 이메일 없음 + 간편 로그인 없음 | 복구 불가 안내 → 가입 시 "이메일 또는 간편 로그인 중 하나를 등록해 두세요" 권장(필수 아님) |

- 1단계(본인)는 운영자가 DB에서 직접 재설정할 수 있으므로 P1로 미뤄도 된다.
- 이메일 발송 서비스가 필요하다(공개 단계). [16 §9]

## 4. 간편 로그인 [검증 반영]

### 4.1 흐름

```
[카카오로 시작하기] → 카카오 인증(동의 화면) → 콜백(인가 코드)
  → 서버: 토큰 교환 → 사용자 정보 조회(회원번호, 닉네임)
  → (provider, provider_user_id) 조회
      ├─ 있음 → 로그인
      └─ 없음 → "처음 오셨나요?" [새로 시작하기] / [기존 계정에 연결하기]  (04 §2.3)
```

- OAuth `state` 값으로 CSRF 방지, PKCE 사용(지원 범위 확인).
- 카카오·네이버 액세스 토큰은 로그인 직후 필요한 정보만 받고 저장하지 않는다. 단, 네이버 캘린더 보내기(07 §5.1)를 켜면 네이버 토큰(갱신 토큰 포함)을 암호화 저장한다.

### 4.2 계정 연결 규칙 [제안]
- 이메일이 같아도 자동 병합하지 않는다.
- 연결은 "로그인한 상태에서 명시적으로" 또는 "간편 로그인 후 기존 계정 로그인"으로만.
- 한 간편 로그인 계정은 이 앱 계정 하나에만 연결.
- 로그인 수단은 최소 1개 남아야 한다.

### 4.3 외부에서 연결 끊김 처리
| 서비스 | 신호 | 처리 |
|---|---|---|
| 카카오 | 연결 끊기 웹훅(사용자가 카카오에서 끊었을 때만, 어드민 키로 출처 검증, **3초 안 200 응답**) | 해당 연결 삭제. 그 계정의 유일한 로그인 수단이었다면 계정은 유지하고, 다음 로그인 시도 시 "카카오 연결이 해제됐어요. 다시 연결하거나 아이디로 로그인해 주세요" |
| 네이버 | 연결끊기 Callback URL(POST, `encryptUniqueId`, 204 응답) | 동일 |
| 앱에서 해제 | 카카오 unlink API / 네이버 `grant_type=delete` | 연결 삭제 + 보안 기록 |

- 웹훅은 빠르게 200/204를 응답하고 실제 처리는 비동기 작업으로.
- **본인 PC + Tailscale 운영(D-043)에서는 카카오·네이버 웹훅이 서버에 도달하지 않는다.** 대신: (1) 다음 간편 로그인 때 카카오·네이버가 "연결되지 않은 사용자"로 응답하면 그 연결을 끊긴 것으로 처리하고 "카카오 연결이 해제됐어요. 다시 연결해 주세요" 안내 (2) 네이버 캘린더 보내기 토큰이 거부되면 같은 처리. 웹훅 수신 코드는 클라우드 이전(3단계)을 위해 남겨 두되 기본 꺼짐. [제안]

### 4.4 개발자 콘솔 준비물 (구현 체크리스트)

| 항목 | 카카오 | 네이버 |
|---|---|---|
| 앱 등록 | 카카오 디벨로퍼스 앱, 카카오 로그인 활성화(꺼져 있으면 KOE004) | 네이버 개발자센터 애플리케이션 |
| Redirect / Callback URL | 정확히 등록(불일치 KOE006). 운영 주소는 `https://oona.<tailnet>.ts.net/api/v1/auth/oauth/kakao/callback`. 사설망 주소 등록 가능 여부·로컬 개발 주소 허용 여부 [미확인] → V-03 | 동일(ts.net 주소, 정확히 일치) |
| 연결 끊기 알림 | (Tailscale 운영에서는 수신 불가 → 위 §4.3 대체 처리) | 동일 |
| 동의 항목 | 닉네임(필수), 프로필 사진(선택) | 식별자, 닉네임 |
| 공개 범위 | 1단계: 테스트(팀 멤버)로 충분 | 1단계: '개발 중' + 멤버 등록 |
| 공개 전 | 비즈 앱 전환 불필요(이메일 안 받으면) | **검수**(영업일 2~3일, 활용처 캡처) |
| 디자인 | 카카오 로그인 버튼 가이드 준수 | 네이버 로그인 버튼 가이드 준수 |
| 연결 끊기 알림 | 웹훅 URL 등록 | 연결끊기 Callback URL 등록 |

## 5. 세션 [제안]

- 서버 저장 세션 + HttpOnly·Secure·SameSite=Lax 쿠키.
- 로그인 유지: 30일(활동 시 연장), 해제 시 브라우저 세션.
- 설치한 PWA는 Safari와 쿠키를 공유하지 않는다(iOS) → 앱에서 다시 로그인 필요. 온보딩·로그인 화면 안내 불필요(자연스럽게 로그인 화면이 뜸). [검증 반영: 19 §7]
- 세션 목록: 기기 이름(사용자 에이전트 요약), 마지막 사용, 개별 폐기.
- 민감 작업(비밀번호 변경, 로그인 연결 해제, 탈퇴, 건강 영구 삭제, 내보내기) 전 재인증(최근 10분 내 인증이 없으면).

## 6. 다중 사용자 확장 [확정: 확장 의도] [제안: 방식]

### 6.1 단계

| 단계 | 가입 | 필요한 준비 |
|---|---|---|
| 1단계 | 본인만. 가입 화면 닫음(초대 코드 필요) | — |
| 2단계 | 초대 코드로 지인 가입 | 이용약관·개인정보 처리방침, 네이버 검수, 구글 OAuth 검증(캘린더 쓰려면) |
| 3단계 | 공개 가입 | 운영 비용·남용 대응, 건강 민감정보 동의, 이메일 발송 |

### 6.2 역할
| 역할 | 권한 |
|---|---|
| 사용자 | 자기 데이터만 |
| 운영자 | 초대 코드 발급, 사용자 정지, 시스템 상태 열람. **사용자 데이터 열람 불가**(운영 도구에 사용자 기록 조회 기능을 만들지 않음) [제안] |

### 6.3 데이터 격리
- 모든 사용자 데이터 행에 `user_id`. 모든 조회·수정은 세션 사용자 ID로 범위를 강제하는 공통 데이터 접근 계층을 거친다.
- 파일 저장 경로도 사용자별(`users/<user_id>/...`), 서명 주소 발급 시 소유자 확인.
- 다른 사용자의 항목 ID로 접근하면 404(존재 여부 비노출).
- 자동 테스트: 사용자 A로 만든 모든 종류의 데이터를 사용자 B 세션으로 조회·수정·삭제 시도 → 모두 실패해야 함(CI 필수).
- DB 행 수준 보안(RLS)으로 이중 방어할지 [미결정 Q-031].

## 7. 탈퇴·완전 삭제 [확정 원칙] [제안: 절차]

1. 탈퇴 신청(재인증) → 계정 상태 `탈퇴 대기`, 즉시 로그아웃, 모든 알림·동기화 중지.
2. 14일 유예: 로그인하면 "탈퇴를 취소할까요?" → 취소 시 복구.
3. 유예 종료: 영구 삭제 작업 — 사용자 데이터 전부(휴지통 포함), 변경 이력, 첨부 파일, 외부 연동 토큰, AI 키, 세션 삭제. 외부 연결 해제(카카오 unlink, 네이버 토큰 폐기, 구글 토큰 폐기).
4. 남기는 것: 감사 로그 중 개인정보 없는 처리 기록("사용자 #해시 영구 삭제 완료, 날짜"), 아이디 재사용 방지용 해시(Q-131).
5. 백업: 백업 보관 기간(30일·12개월) 만료로 소멸. 복구 시 삭제 대상 목록을 다시 적용하는 절차를 둔다(삭제된 사용자가 백업 복원으로 되살아나지 않게). [14 §6]

## 8. 우선순위

| 기능 | 우선 |
|---|---|
| 아이디 가입·로그인, 카카오·네이버 로그인, 세션, 데이터 격리 | P0 |
| 로그인 연결·해제, 기기 관리, 비밀번호 찾기, 탈퇴·완전 삭제, 외부 끊김 웹훅 | P1 |
| 초대 코드, 운영자 역할 | P1(2단계 전) |
| 2단계 인증 | P2 |
| 인증 라이브러리 선택 | **Better Auth로 결정(V-11 검증, 2026-11-01)**. 구현 메모: ① 라이브러리가 이메일을 필수로 요구 → 이메일 없는 계정은 내부 주소 `<종류>.<id>@users.oona.invalid`를 넣고 화면에는 "없음"으로 표시(사용자가 이메일을 등록하면 실제 주소로 교체) ② 카카오·네이버는 기본 요청 권한에서 이메일을 빼고(`disableDefaultScope`) 내부 주소로 대체 ③ `disableImplicitSignUp`으로 간편 로그인 자동 가입을 막고, 처음 온 사람은 "처음 오셨나요?"에서 새로 시작(다시 인증 + `requestSignUp`) 또는 기존 계정 연결(아이디 로그인 후 `linkSocial`) — 새로 시작은 인증을 한 번 더 거침 ④ `disableImplicitLinking`으로 이메일 자동 병합 금지 ⑤ 마지막 로그인 수단 해제는 라이브러리가 기본 차단 ⑥ 오류 문구가 영어 → 오류 코드별 한국어 문구표 필요 |
