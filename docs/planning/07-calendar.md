## 2. 일정 기본 기능 [제안]

### 2.1 일정 필드

| 필드 | 필수 | 규칙 |
|---|---|---|
| 제목 | 필수 | 1~100자 |
| 종일 | | 기본 끔 |
| 시작·종료 | 필수 | 종일이면 날짜만. 종료 ≥ 시작. 여러 날 일정 가능 |
| 시간대 | 자동 | 사용자 설정 시간대(기본 Asia/Seoul). 외부 일정은 원래 시간대 보존 |
| 반복 | | RRULE(iCalendar 표준) 저장 |
| 알림 | | 0~3개, 각 "n분/시간/일 전" |
| 캘린더 | 필수 | 내 캘린더(여러 개 만들 수 있음: 개인, 일, 가족…) 또는 연결된 외부 캘린더 |
| 장소 | | 텍스트 |
| 메모 | | |
| 출처 | 자동 | 이 앱 / 구글 / 카카오 / 네이버(CalDAV) |

### 2.2 내 캘린더

- 기본 캘린더 "내 일정" 1개 + 사용자 추가(이름, 색 — 일정 색은 트래커 팔레트와 같은 12색을 재사용 [제안]).
- 캘린더 단위로 보이기/숨기기.

### 2.3 반복 일정

- 저장: 원본 일정 + RRULE + 예외 목록(특정 회차 수정·삭제).
- 수정 범위: 이 일정만(예외 생성) / 이후 일정(원본을 그 전날로 끝내고 새 반복 일정 생성 — 분할) / 모든 일정(원본 수정).
- 화면에 보여 줄 때는 보기 범위(한 달·한 주) 안의 회차만 계산해서 펼친다.
- 구글 연동 시 구글의 반복·예외 모델(`recurringEventId`, `originalStartTime`, `status: cancelled`)과 1:1로 대응되게 저장한다. [검증 반영: 19 §1.4]

### 2.4 알림

- 정시에 울려야 하므로 **서버가 웹 푸시를 보낸다.** 기기 타이머에 의존하지 않는다. [검증 반영: iOS는 백그라운드 동기화 없음]
- iOS는 홈 화면에 추가한 앱에서만 웹 푸시를 받는다. 설정 > 알림에서 안내. 앱을 설치하지 않은 iOS 사용자는 앱을 열었을 때 펫 말풍선·알림 센터로만 확인.
- 앱 사용 중이면 펫 말풍선으로도 보여 준다(중복 시 푸시는 생략 [제안]).

### 2.5 다른 영역 겹쳐 보기 (오버레이) [제안] P1

| 오버레이 | 기본 | 표시 |
|---|---|---|
| 고정 지출 결제일 | 켬 | 💳 이름 |
| 해지 예정일 | 켬 | ⚠ 이름 해지 |
| 작품 기록 | 끔 | 📚/🎬 제목 |
| 생리 예정일 | **끔** | 건강 잠금 시 표시 불가 |
| 큰 지출 | 끔 | 예산에 날짜가 있으면 |

- 오버레이는 일정 데이터가 아니다. 외부 캘린더로 보내지 않는다.

## 3. 연동 전략 요약 [검증 반영]

| 서비스 | 공식으로 가능한 것 | 1단계(본인) | 다중 사용자 단계 |
|---|---|---|---|
| 구글 캘린더 | 읽기·쓰기·증분 동기화·푸시 | **가져오기 → 양방향** | 양방향(구글 OAuth 앱 검증 필요) |
| 네이버 캘린더 | **일정 추가만**(조회·수정·삭제 API 없음) | 앱 → 네이버 보내기 + (선택) CalDAV 고급 연결 | 앱 → 네이버 보내기만 |
| 카카오 톡캘린더 | 생성·조회·수정·삭제 | **본인(앱 팀 멤버)은 심사 없이 사용 가능** | 권한 심사 필요 |
| ICS 구독 주소 | 서비스마다 다름 | 범용 "주소로 가져오기"(읽기 전용) | 동일 |

> 사용자에게 할 답: "구글 캘린더는 양쪽에서 함께 고칠 수 있게 연결할 수 있어요. 네이버 캘린더는 공식적으로는 이 앱에서 만든 일정을 네이버로 보내는 것만 돼요. 네이버 일정을 이 앱으로 가져오려면 네이버 2단계 인증의 앱 비밀번호를 쓰는 고급 연결이 필요하고, 이건 본인 전용으로만 열어 둘게요."

## 4. 구글 캘린더 [검증 반영: 19 §1]

### 4.1 단계

| 단계 | 기능 | 권한 범위 | 비고 |
|---|---|---|---|
| G1 가져오기 | 선택한 캘린더의 일정을 읽어 와 표시(읽기 전용) | `calendar.calendarlist.readonly`, `calendar.events.readonly` | P1 |
| G2 함께 고치기 | 이 앱에서 외부 일정 수정·삭제·생성 → 구글 반영 | `calendar.events` (또는 `calendar.events.owned`) | P2 |
| G3 실시간 | 구글 변경 즉시 반영(푸시) | 동일 + 공개 HTTPS 주소 | G2와 함께 |

### 4.2 동기화 방식

```
연결 직후:  전체 가져오기(기간: 1년 전 ~ 1년 후 [제안]) → nextSyncToken 저장
주기 동기화: (G1) 15분마다 + 앱을 열 때 + 사용자 "지금 가져오기"
            (G3) 푸시 알림 수신 시 즉시 + 하루 1회 안전 동기화
변경분:     syncToken으로 요청 → 추가/수정/삭제 반영
410 Gone:   로컬 외부 일정 사본 비우고 전체 다시 가져오기(사용자에게 알리지 않음, 로그만)
```

- 푸시 채널(watch)은 자동 갱신이 없다 → 서버 예약 작업이 만료 하루 전에 새 채널을 만든다. 갱신 중 두 채널이 겹치는 것을 허용(중복 알림은 syncToken 조회로 무해).
- 푸시는 **HTTPS 공개 주소가 필요하다.** 외부 접속을 Tailscale 사설망으로 정했으므로(D-043) **G3(실시간 푸시)는 쓰지 않는다.** 구글 변경은 15분 주기 + 앱을 열 때 + `지금 가져오기`로 가져온다. 구글에서 고친 일정이 이 앱에 보이기까지 최대 15분 걸릴 수 있다. G1(가져오기)·G2(양방향)는 서버가 바깥으로 요청하는 방식이라 그대로 가능하다.
- 실시간 반영이 꼭 필요해지면 Tailscale Funnel로 구글 알림 수신 경로만 공개하는 방법이 있다 [Q-164, 추천: 쓰지 않음].
- PC가 꺼져 있던 동안의 변경은 다시 켜질 때 syncToken으로 한 번에 가져온다. 푸시 채널이 그사이 만료됐으면 새로 등록한다. [16 §5.5]
- syncToken 요청에 쓰는 파라미터 조합을 첫 요청부터 고정한다(섞으면 400).

### 4.3 양방향 충돌 정책 (G2) [제안]

| 상황 | 처리 |
|---|---|
| 앱에서 수정 → 구글 반영 성공 | 정상 |
| 앱에서 수정 → 구글 실패(네트워크·권한) | 앱에 저장 + "보내기 대기" 표시, 재시도(지수 백오프 최대 24시간), 실패 지속 시 알림 |
| 같은 일정을 양쪽에서 거의 동시에 수정 | 구글의 `updated` 시각과 앱의 수정 시각 비교, **나중 것이 이김**. 진 쪽 내용은 변경 이력에 보존 |
| 구글에서 삭제 | 앱에서도 삭제(휴지통이 아닌 "외부에서 삭제됨"으로 숨김 — 외부 일정은 휴지통 복구 대상 아님 [제안]) |
| 앱에서 외부 일정 삭제 | 구글에 삭제 요청. 성공하면 숨김 |
| 연결 해제 | 가져온 외부 일정 사본 삭제(외부 원본은 그대로) |

### 4.4 OAuth 앱 운영 [검증 반영]

- **테스트 상태(Testing)로 두면 refresh token이 7일 만에 만료**된다 → 1단계에도 "Production 게시 + 미검증" 상태로 운영(로그인 시 "확인되지 않은 앱" 경고 1회, 본인 사용 문제없음).
- 미검증 앱은 신규 사용자 평생 100명 한도. 다중 사용자 공개 전에 sensitive 범위 검증(개인정보처리방침, 도메인, 시연 영상) 일정 확보 — 수개월 소요 가능.
- 구글 로그인은 앱 로그인 수단이 아니다(로그인은 카카오·네이버·아이디만 [확정]). 구글은 **캘린더 연결 전용 인증**으로만 쓴다.
- 쿼터: 사용자당 분당 600건. 1인 사용에는 충분. 과금 여부 [미확인] → 콘솔 확인 [18 Q-081].

## 5. 네이버 캘린더 [검증 반영: 19 §2]

### 5.1 공식 경로: 보내기 (N1) P1

- 네이버 로그인 토큰에 캘린더 권한을 받아 `일정 추가` API 호출.
- 동작: 이 앱 일정 추가·수정 화면의 `네이버 캘린더에도 추가` 체크(연결 시). 또는 캘린더 설정에서 "이 캘린더의 새 일정은 네이버에도 추가".
- 한계(사용자에게 ⓘ로 안내): 네이버로 보낸 뒤 이 앱에서 수정·삭제해도 네이버에는 반영되지 않는다. 네이버에서 만든 일정은 가져올 수 없다.
- 반복 일정은 iCalendar 문자열(RRULE 포함)로 보낸다.
- 네이버 로그인 연결이 없는 사용자(아이디 가입)는 "네이버로 연결" 인증을 추가로 거친다(로그인 연결과 같은 인증을 재사용).

### 5.2 고급 연결: CalDAV (N2) [검증 필요] P2, 1단계 본인 전용

- 서버 `caldav.calendar.naver.com`, 네이버 아이디 + **애플리케이션 비밀번호**(2단계 인증 후 발급).
- 가능: 조회·생성·수정·삭제 → 구글과 비슷한 양방향.
- 위험·제약: 공식 개발자 API가 아님, 네이버 쪽 변경에 취약, 자격증명을 서버에 보관해야 함(암호화 저장, 감사 로그).
- 정책: **다중 사용자 단계에서는 제공하지 않는다.** 1단계에서도 기본 숨김, 가이드 안에서만 진입. 사용자가 직접 앱 비밀번호를 입력한다.
- 구현 전 검증: 실제 연결 테스트(조회·수정·반복 일정·삭제), 동기화 방식(CTag/ETag 기반 변경 감지). [18 Q-082]

### 5.3 ICS 구독 주소

- 개인 네이버 캘린더의 ICS 구독 주소 제공 여부 [미확인]. 확인되면 "주소로 가져오기"(읽기 전용)로 N2보다 안전한 대안이 된다.

## 6. 카카오 톡캘린더 [검증 반영: 19 §3.2] [제안] P2

- 사용자가 직접 요청하지 않았으나 카카오 로그인을 이미 쓰므로 후보로 기록. 사용자 확인 필요 [18 Q-083].
- 1단계: 본인 계정이 카카오 개발자 앱 팀 멤버이면 권한 심사 없이 일정 생성·조회·수정·삭제 가능 → 양방향 가능.
- 다중 사용자: `talk_calendar` 동의항목 + 권한 심사(이용 흐름·화면 캡처). 일 30,000건 한도.

## 7. 범용 ICS 주소 가져오기 [제안] P2

- 공휴일, 스포츠 경기, 회사 공유 캘린더 등 ICS 주소를 붙여넣으면 읽기 전용 캘린더로 추가. 6시간마다 새로 가져오기.
- 한국 공휴일은 기본 제공 캘린더로 내장할지 [미결정 Q-084] (추천: 내장, 끌 수 있음).

## 8. 동기화 상태와 오류 (화면 표시)

| 상태 | 내부 원인 | 화면 |
|---|---|---|
| 정상 | | 설정에 "5분 전 가져옴" |
| 가져오는 중 | 첫 동기화 | 캘린더 상단 진행 띠 |
| 연결 끊김 | refresh token 무효(사용자가 구글에서 권한 해제, 6개월 미사용, 비밀번호 변경) | InlineNotice "구글 캘린더 연결이 끊겼어요" `[다시 연결]` + 알림 1회 |
| 권한 부족 | 사용자가 동의 화면에서 일부 권한 해제 | "일정 쓰기 권한이 없어 가져오기만 할 수 있어요" `[권한 다시 받기]` |
| 일시 오류 | 429·5xx | 화면 표시 없이 재시도. 6시간 넘게 실패하면 "잠시 가져오지 못하고 있어요" |
| 보내기 대기 | 앱 → 외부 쓰기 실패 | 일정에 `cloud-off`, 상세에 `다시 보내기` |

## 9. 시간대·날짜 규칙 [제안]

- 저장은 UTC + 원래 시간대 이름. 종일 일정은 날짜만(시간대 없음).
- 화면은 사용자 설정 시간대로 표시. 해외 출장 시 설정을 바꾸면 모든 시간 일정이 그 시간대로 보인다.
- 일광 절약 시간이 있는 시간대의 반복 일정은 원래 시간대 기준으로 펼친다(RRULE 표준 처리 라이브러리 사용).
