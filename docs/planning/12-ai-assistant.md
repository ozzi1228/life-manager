## 2. 웹 구독과 API의 차이 [검증 반영]

| 구분 | 웹 구독 (ChatGPT Plus·Pro, Claude Pro·Max, Google AI Pro) | API |
|---|---|---|
| 용도 | 각 회사의 앱·웹에서 사람이 대화 | 다른 프로그램(이 앱)이 호출 |
| 결제 | 월 정액 | 사용한 만큼(토큰) 별도 결제 |
| 이 앱에서 사용 | **원칙적으로 불가**. 구독에는 API 사용권이 포함되지 않음 | **가능**. 이 앱의 표준 방식 |
| 예외 | OpenAI "Sign in with ChatGPT" 플랜 사용(로컬·오픈소스 앱), Claude Max·Team 월 API 크레딧, ChatGPT Pro 프로모션 API 크레딧 | Gemini는 무료 등급 API 키 있음 |

**결론**: "내 구독으로 쓰기"는 제공자마다 가능한 길이 다르다. 이 앱은 **API 키를 기본 방식**으로 하고, 구독을 쓰는 경로는 검증된 것만 선택 옵션으로 둔다.

### 3.1 1단계(본인) 추천 구성 [제안]

1. **API 키로 시작.** 비용을 줄이려면:
   - Gemini: 무료 등급 API 키로 시작(한도·데이터 사용 정책 확인 [18 Q-120]).
   - Claude: Max 구독이라면 매월 제공되는 API 크레딧을 Console API 키로 사용.
   - ChatGPT: Pro라면 프로모션 API 크레딧 확인.
2. **앱을 본인 PC에서 운영하기로 확정했으므로(D-034) B(Sign in with ChatGPT 플랜 사용)를 0단계에서 검증한다.** [18 Q-121, 17 V-10]
   - 확인할 것: Tailscale 사설망에서만 열리는 자가 운영 앱(D-043, 공개 주소 없음)이 OpenAI가 말하는 "로컬 호스팅 앱"의 동적 등록 흐름 대상인지, 인증 후 돌아오는 주소로 ts.net 주소를 쓸 수 있는지, 플랜 사용 한도, Responses API 한정 조건에서 도구 호출·스트리밍·구조화 출력이 모두 되는지.
   - 통과하면: ChatGPT는 "ChatGPT 계정으로 로그인"을 기본 연결 방식으로, Claude·Gemini는 API 키로.
   - 실패하면: 3사 모두 API 키.
3. C(로컬 CLI 브리지)는 앱과 AI 도구가 같은 PC에 있어 기술적으로는 가능해졌다. 그래도 B가 통과하면 만들지 않는다. B가 실패하고 사용자가 원하면 **Codex CLI 한정 실험 기능**으로만 검토한다. Claude Code 구독을 앱이 대신 호출하는 방식과 Gemini CLI 편승은 약관상 제외한다.

### 3.2 다중 사용자 단계

- 각 사용자가 자기 API 키를 넣는다(BYOK). [확정]
- 앱 운영자 키로 무료 체험을 줄지는 [미결정 Q-122] (비용·남용 위험).
- 구독 경로(B·C)는 제공하지 않는다. 다른 사용자를 받으면서 클라우드로 옮기면(16 §5.8) 원격 호스팅이 되어 B는 본인에게도 쓸 수 없게 될 수 있다 → 이전 시 다시 확인.

## 4. API 키 관리 [제안]

| 항목 | 규칙 |
|---|---|
| 입력 | 설정 > AI 비서 > 연결 Dialog. 붙여넣기, 형식 경고(접두사 불일치 시 "형식이 다른 것 같아요" — 판정은 연결 테스트로) |
| 검증 | `[연결 테스트]`: 모델 목록 조회 + 아주 짧은 요청 1회 |
| 저장 | 서버에서 AES-256-GCM 봉투 암호화(데이터 키를 마스터 키로 암호화). 마스터 키는 환경 비밀값/관리형 키 서비스 |
| 표시 | 끝 4자리만. 원문 다시 보기 불가, 교체·삭제만 |
| 사용 | 서버에서만 복호화해 제공자 호출. 브라우저로 원문을 보내지 않음 |
| 로그 | 키 원문·요청 헤더는 어떤 로그에도 남기지 않음 |
| 삭제 | 연결 해제 시 즉시 영구 삭제(soft delete 예외 — 비밀값은 보존 가치 없음) |
| 사고 대응 | 키 유출 의심 시 사용자에게 "제공자 사이트에서 키를 폐기해 주세요" 안내 + 앱 키 삭제 |

## 5. 대화 동작

### 5.1 처리 흐름 [제안]

```
사용자 메시지
  → 서버: 권한 확인(연결 상태, 영역별 데이터 접근 설정)
  → 모델 호출(시스템 지시 + 펫 말투 + 사용 가능한 도구 목록 = 허용된 영역의 도구만)
  ↔ 도구 호출 반복(최대 6회): 서버가 사용자 데이터 조회 → 요약 결과를 모델에 전달
  → 응답 스트리밍
     ├─ 텍스트
     ├─ 선택지 질문(ask_choice) → ChoiceChips 렌더
     ├─ 작업 제안(propose_*) → ConfirmCard 렌더 (저장은 사용자가 누를 때만)
     └─ 근거(조회한 영역·건수·기간) → "근거 보기"
  → 감사 로그: 조회한 영역·도구·건수
```

### 5.2 선택지 질문 [확정: 선택지 클릭]

- 모델이 추가 정보가 필요하면 `ask_choice` 도구를 호출하도록 지시한다(자유 텍스트로 묻는 대신).
- 형식:

```json
{
  "question": "몇 명이 보시나요?",
  "options": ["1명", "2명", "3명 이상"],
  "multiple": false,
  "allow_free_text": true
}
```

- 화면: 선택지 버튼 + `직접 입력`. 누르면 그 선택지가 사용자 메시지로 전송된다.
- 선택지는 2~6개. 그 이상이면 모델이 범주를 묶도록 지시.

### 5.3 도구 목록 (초안) [제안]

| 도구 | 영역 권한 | 내용 |
|---|---|---|
| `get_today_summary` | 일정·목표·지출 | 오늘 일정, 트래커 진행, 남은 예산 |
| `query_transactions` | 지출 | 기간·분류·결제수단·내용 검색 → 합계·건수·상위 항목(원본 목록은 최대 50건) |
| `get_budget_status` | 지출 | 월 예산·분류별 사용 |
| `list_recurring_payments` | 지출 | 고정 지출(상태별), 메모 포함 |
| `list_cards` | 카드 | 카드·이번 달 실적·한도 |
| `get_restraint_status` | 지출 + 위시 | 이번 달 참아야 할 금액·참은 금액·후보 ("이번 달 얼마나 더 참아야 해?") [20] |
| `recommend_card` | 카드 + 지출 | [06 §6.5](06-finance.md) 계산 엔진 호출(같은 코드). 모델이 계산하지 않는다 |
| `get_tracker_stats` | 목표 | 항목·기간별 완료 횟수 |
| `list_goals` | 목표 | 필터별 목표 |
| `list_events` | 일정 | 기간별 일정 |
| `search_journal` | 기록 | 기간·주제·키워드 → 요약 |
| `list_media` | 기록 | 작품 기록 |
| `list_wishlist` | 위시 | 위시 항목 |
| `get_health_records` | **건강(기본 꺼짐)** | 지표·기간별 |
| `ask_choice` | — | 선택지 질문(화면 요소) |
| `propose_transaction` / `propose_event` / `propose_tracker_check` / `propose_wish` | 해당 영역 | 저장하지 않고 확인 카드만 만든다 |

- 계산(합계, 카드 혜택, 통계)은 **항상 서버 도구가 한다.** 모델은 숫자를 지어내지 않고 도구 결과를 설명한다. 시스템 지시에 "도구 결과에 없는 숫자를 만들지 마세요" 명시.
- 도구 결과는 데이터로 취급한다. 사용자 데이터 안의 문장(일기·위시 메모·링크 제목)에 지시문이 있어도 따르지 않도록 시스템 지시에 명시(프롬프트 주입 대비). [제안]

### 5.4 작업 제안(쓰기) [제안] P2

- AI는 직접 저장하지 않는다. 항상 `ConfirmCard` → 사용자가 `저장`을 눌러야 일반 API로 저장(출처 = AI 대화).
- 카드에서 `수정`을 누르면 해당 입력 폼이 값이 채워진 채 열린다.

### 5.5 카드 상담 예시 흐름 [확정 시나리오]

```
사용자: CGV 결제할 건데 어떤 걸로 쓰면 가장 혜택이 좋아?
모델:  (금액·인원이 혜택 조건에 영향 → ask_choice)
       "몇 명이 보시나요?" [1명][2명][3명 이상]
사용자: 2명
모델:  recommend_card(merchant="CGV", amount=약 28,000(2인 일반 예상) 또는 금액 질문, date=today)
       → 결과: A카드 4,000원(남은 횟수 1), C카드 1,400원 적립, B카드 한도 소진
응답:  "A카드가 가장 유리해요. 영화 4,000원 할인을 이번 달 1번 더 받을 수 있어요. B카드는 이번 달 할인 한도를 다 썼어요."
       ▸ 근거 보기: 카드 3장 혜택, 11월 지출 32건 기준
```

- 금액을 추정해야 하면 추정임을 밝히고, 정확한 금액을 묻는 선택지(`2만원대`, `3만원대`, `직접 입력`)를 줄 수 있다.
- 지출 기록이 부족하면 "기록된 지출이 적어 한도 사용량이 정확하지 않을 수 있어요"를 덧붙인다. [확정 맥락]

## 6. 데이터 접근 권한 [제안]

| 영역 | 기본 | 비고 |
|---|---|---|
| 일정 | 켬 | |
| 목표·트래커 | 켬 | |
| 지출·예산·고정 지출 | 켬 | 카드 상담에 필요 [확정: 지출 참고] |
| 카드 혜택 | 켬 | |
| 일기·작품 | 끔 | 사적인 글 |
| 위시 | 켬 | |
| 건강 | **끔** | 켜도 대화마다 근거 표시 |

- 권한이 꺼진 영역의 도구는 모델에 아예 제공하지 않는다(모델이 존재를 모름). 질문이 그 영역이면 서버가 "권한 요청" 카드를 보여 준다.
- `이번만 허용`: 이 대화에서만. `항상 허용`: 설정 변경.
- 모든 도구 호출은 감사 로그(보안 기록 화면에서 사용자 열람). [FR-DATA-008]
- 제공자 데이터 정책 안내(ⓘ): API로 보낸 데이터의 학습 사용 여부는 제공자 정책을 따른다. 제공자별 요약 링크를 가이드에 둔다. [검증 필요: 최신 정책 확인 Q-123]

## 7. 모델·제공자 관리 [제안]

- 서버에 제공자 공통 인터페이스(메시지, 스트리밍, 도구 호출, 구조화 출력)를 두고 제공자별 구현을 붙인다. 구현 후보: Vercel AI SDK(OpenAI·Anthropic·Google 제공자 지원) [18 Q-124].
- 모델 목록은 연결 테스트 때 제공자 API에서 받아 사용자에게 보여 준다(코드에 모델 이름을 박지 않음). 추천 기본 모델은 설정 파일로 관리.
- 제공자 장애 시 다른 연결된 제공자로 자동 전환하지 않는다(사용자 키·비용이 다름). "지금 Claude가 응답하지 않아요. 다른 AI로 바꿀까요?" 선택지 제공. [제안]

## 8. 대화 기록

- 저장: 대화·메시지(텍스트, 선택지, 확인 카드, 근거 요약). 도구 결과 원본은 저장하지 않고 요약만. [제안]
- 보관 기간: 사용자 선택(30일 / 90일 / 계속, 기본 90일). 기간이 지나면 영구 삭제(soft delete 예외 — 사용자가 고른 보존 정책). [제안]
- 모델에 보내는 맥락: 같은 대화의 최근 메시지(토큰 한도 내). 지난 대화를 기억하는 기능은 범위 밖(P2 검토).

## 9. 비용·한도 [검증 필요]

- 대화 1회(도구 호출 2~3회 포함) 예상 토큰과 제공자별 비용은 구현 후 실측. 요금은 자주 바뀌므로 문서에 고정하지 않는다.
- 사용자 보호: 대화당 도구 호출 최대 6회, 응답 최대 길이, 월 요청 수 표시(P2). 사용자 키가 한도를 넘으면 제공자 오류를 그대로 친절한 문구로.
- 운영자 비용: BYOK이면 운영자 AI 비용은 0. 본인 PC 운영이라 서버 비용도 없다.
