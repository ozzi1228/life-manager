# 06. 돈 관리: 지출·예산·고정 지출·카드 혜택·자산

> 문서 상태: 초안 v0.1 · 작성일 2026-11-01
> 화면: [04 §6](04-screen-specifications.md#6-자산) · 데이터: [14 §4.4](14-data-model.md) · API: [15 §6](15-api-specifications.md) · 조사: [19 §5](19-integration-research.md#5-국내-신용카드-혜택-데이터)

## 1. 사용자 요구 원문 정리 [확정]

- 재테크 및 예산·지출 관리. 마이데이터 연동은 필요 없고 직접 입력하면 된다.
- 예산은 고정 지출 내역을 저장해 둘 수 있어야 한다.
- 고정 지출 건별로 메모를 남길 수 있어야 한다. (예: 네이버플러스 멤버십에 넷플릭스 이용권 포함)
- 고정 지출 해지 관리: "다음 달까지 쓰고 해지" 같은 경우 목록에서 빼야 하나, 해지 표시하고 맨 밑으로 내려야 하나? (질문)
- 월별 예산: 그 달 크게 나갈 돈은 따로 입력, 그 외는 범위별 예산.
- 지출 내역에 라벨을 붙여 예산 초과 여부·사용 여부를 확인.
- 카드 혜택 관리. API로 처리할 수 있나? 카드 혜택을 저장하고 최대 혜택으로 쓰는 법을 분석.
  - 분석은 사용자가 지출을 꼼꼼히 입력했을 때 가능하고, 아니면 사용자가 보고 판단.
  - 챗봇: "CGV 결제할 건데 어떤 카드가 좋아?" → 답변 또는 추가 질문. 추가 질문의 선택지는 클릭.
  - 입력한 지출 내역이 있으면 읽어 와 참고.

## 2. 용어 [제안]

| 화면 용어 | 뜻 | 내부 |
|---|---|---|
| 지출 / 수입 | 직접 입력한 돈의 흐름 | `transaction(type)` |
| 분류 | 지출에 붙이는 묶음(식비, 교통…). 사용자가 말한 "라벨" | `category` |
| 분류별 예산 | 분류마다 정한 월 한도. 사용자가 말한 "범위별 예산" | `budget_line` |
| 큰 지출 | 그 달에만 크게 나가는 돈의 계획(여행, 경조사) | `planned_expense` |
| 고정 지출 | 주기적으로 나가는 돈(구독, 통신비, 보험) | `recurring_payment` |
| 결제수단 | 카드·계좌·현금·간편결제 | `payment_method` |
| 카드 | 혜택·실적을 관리하는 신용·체크카드 | `card` (결제수단의 한 종류) |
| 실적 | 카드 혜택 조건 계산에 인정되는 사용 금액 | `card_performance` |
| 사치 | 쓴 돈만큼 참은 소비 목록을 채워야 하는 분류 [확정] | `category.counts_toward_restraint` |
| 참은 소비 | 진짜 사고 싶었는데 참은 것의 목록 [확정] → [20](20-restraint-spending.md) | `restraint_entry` |

"라벨"이라는 화면 단어는 쓰지 않는다. 한 지출에 여러 개 붙이는 자유 태그가 필요하면 P2에서 `태그`로 추가한다. → [18 Q-030](18-decisions-and-open-questions.md)

## 3. 지출·수입

### 3.1 필드

| 필드 | 필수 | 규칙 |
|---|---|---|
| 종류 | 필수 | 지출 / 수입 |
| 금액 | 필수 | 1원 이상 정수, 최대 100억 원 |
| 날짜 | 필수 | 기본 오늘. 미래 날짜는 "예정" |
| 분류 | 필수 | 지출 분류 또는 수입 분류 |
| 결제수단 | 선택 | 카드 실적·혜택 분석에 쓰임 |
| 내용 | 선택 | 가맹점·내용, 최대 60자 |
| 메모 | 선택 | |
| 할부 | 선택 | 일시불 / 2~24개월 (카드 결제수단만) |
| 큰 지출 연결 | 선택 | 그 달 큰 지출 계획 1개 |
| 출처 | 자동 | 직접 입력 / 위시 구매 / 고정 지출 자동 기록 / AI 대화 / 가져오기 |

### 3.2 규칙

1. **환불·취소**: 같은 분류의 수입으로 넣지 않고, 지출에 `환불` 표시를 한 음수 지출로 기록한다(분류 합계·카드 실적에서 차감). 화면: 지출 입력에서 금액 앞 `−` 토글 또는 원래 지출 `···` → `환불 기록`. [제안]
2. **할부**: 예산에는 결제 시점 전액이 아니라 [미결정 Q-032] (a) 전액을 결제한 달에 반영 (b) 월 할부금을 각 달에 반영. 추천은 (a) — 직접 입력 앱에서 단순함이 중요하고, 사용자의 체감 지출과 맞는다. 카드 실적은 카드사마다 다르므로 카드 설정의 `할부 실적 인정 방식`을 따른다.
3. **나눠 내기(더치페이)**: 내가 낸 금액만 기록. 전체 금액과 받을 돈 관리는 범위 밖. [제안]
4. **미래 날짜(예정)**: 예산 "쓴 돈"에는 포함하지 않고 "예정"으로 따로 보여 준다. 날짜가 되면 자동으로 쓴 돈에 포함.
5. **분류 없는 지출 없음**: 분류는 필수(예산 계산이 깨지지 않도록). 가져오기 데이터는 `기타`로 들어가고 "분류가 필요한 지출 5건" 안내.

## 4. 월별 예산

### 4.1 계산식 [확정: 큰 지출 개별 + 범위별] [제안: 계산식]

```
이번 달 예산(총)   = 고정 지출 합계(자동) + 큰 지출 계획 합계 + 분류별 예산 합계
이번 달 쓴 돈      = 이번 달 지출 합계(예정 제외, 환불 차감)
남은 예산          = 이번 달 예산 − 이번 달 쓴 돈

분류 c의 사용      = 분류 c 지출 합계 (큰 지출에 연결된 지출, 고정 지출에서 생긴 지출 제외)
분류 c의 남은 돈    = 분류별 예산(c) − 분류 c의 사용
큰 지출 p의 사용    = p에 연결된 지출 합계
고정 지출 합계      = 이번 달 결제일이 있는 이용 중·해지 예정(마지막 이용일 이전 결제분) 고정 지출 금액 합
```

- 지출이 큰 지출이나 고정 지출에 연결되면 분류별 사용에서 빠진다. 같은 돈이 두 번 계산되지 않는다.
- 고정 지출을 자동 기록하지 않는 사용자도 있다. 그 경우 고정 지출 합계는 "예정 금액"으로 예산에 들어가고, 사용자가 같은 결제를 지출로 직접 입력하면 중복된다. 해결: 지출 입력 시 내용·금액이 고정 지출과 비슷하면 "고정 지출 '넷플릭스'의 결제인가요?" 칩 → 탭하면 연결. [제안]

### 4.2 상태 기준 [제안]

| 상태 | 조건 | 표시 |
|---|---|---|
| 여유 | 사용 < 80% | 기본 |
| 주의 | 80% ≤ 사용 < 100% | warning, 알림(설정 시) |
| 초과 | 사용 ≥ 100% | destructive-text, "○원 초과" |
| 예산 없음 | 분류별 예산 미설정 분류의 지출 | "예산 없는 분류"로 묶어 합계만 |

### 4.3 월 넘어가기

- 새 달 첫 진입: 이번 달 예산이 없으면 "지난달 예산을 복사할까요?" `[복사]` `[새로 정하기]`.
- 예산 편집의 `다음 달에도 같은 예산 쓰기`가 켜져 있으면 분류별 예산을 자동 복사(큰 지출은 복사하지 않음). [제안]
- 월 시작일: 기본 1일. 급여일 기준(예: 25일 시작) 예산 기간 설정은 [미결정 Q-033] — 요구가 있으면 P1.

## 5. 고정 지출

### 5.1 필드

[04 §6.7](04-screen-specifications.md#67-고정-지출-상세추가수정해지-scr-fin-07) 표 참조. 추가 내부 필드: 상태, 마지막 이용일, 해지일, 시작일, 다음 결제일(계산값, 저장하지 않거나 캐시).

### 5.2 주기와 결제일 계산 [제안]

| 주기 | 입력 | 다음 결제일 계산 |
|---|---|---|
| 매월 | 일(1~31) 또는 "말일" | 이번 달 그 날이 지났으면 다음 달. 그 달에 없는 날(31일)은 그 달 말일 |
| 매년 | 월·일 | 2월 29일은 평년에 2월 28일 |
| N개월마다 | 기준 월·일, N(2~12) | 기준 월부터 N개월 간격 |
| 매주 | 요일 | 다음 그 요일 |

- 주말·공휴일 결제일 이동(카드사 규칙)은 반영하지 않는다. 예정일은 "약속된 날" 기준. [제안]
- 결제일 계산 기능은 단위 테스트 필수(말일, 윤년, 12월→1월).

### 5.3 해지 관리 (사용자 질문에 대한 설계) [제안]

**답: 목록에서 빼지 않는다. 상태로 관리하고 해지된 항목은 맨 아래 접힌 묶음으로 내린다.**

| 상태 | 들어가는 방법 | 결제 예정·예산 | 알림 | 목록 위치 |
|---|---|---|---|---|
| 이용 중 | 추가 시 기본, `다시 이용하기` | 포함 | 결제일 알림 | 기본 목록 |
| 해지 예정 | `해지 예정으로 바꾸기` + 마지막 이용일 | 마지막 이용일 **이전** 결제분만 | 마지막 이용일 3일 전 | 기본 목록(배지) |
| 해지됨 | 마지막 이용일 다음 날 자동, 또는 `바로 해지됨으로` | 제외 | 없음 | 맨 아래 `해지됨` 묶음(접힘) |

이유:
- 해지한 항목의 메모·납부 이력은 "다시 가입할까", "얼마나 냈나" 판단에 쓸모가 있다.
- 목록에서 지우면 실수로 지웠을 때와 구분이 안 된다. 삭제(휴지통)는 별도 동작으로 남긴다.
- "다음 달까지 쓰고 해지"는 해지 예정 상태로 정확히 표현된다.

### 5.4 자동 기록 [제안] P1

- 항목별 `자동 기록` 켜면 결제일 오전(사용자 시간대 09:00)에 서버 작업이 지출을 만든다. 출처 = 고정 지출, 분류 = 고정 지출의 분류, 결제수단 = 고정 지출의 결제수단.
- 이미 그 결제 주기에 연결된 지출이 있으면(사용자가 직접 입력해 연결함) 만들지 않는다.
- 알림: "넷플릭스 13,500원을 기록했어요" (`되돌리기`는 알림 센터에서 지출 삭제로).
- 금액이 바뀌는 고정 지출(전기요금 등): `금액이 매번 달라요` 체크 → 자동 기록 대신 결제일 알림만 "전기요금을 기록해 주세요" + 바로 입력 버튼.

### 5.5 메모 [확정]

- 메모는 목록에서 아이콘으로 존재를 알리고, PC Hover Card·모바일 행 아래 첫 줄 미리보기로 바로 보인다.
- 다른 고정 지출과의 관계(포함 혜택)를 구조화할지: [미결정 Q-034]. 추천은 **메모 유지 + 선택적 "포함된 서비스" 연결**(예: 네이버플러스 → 넷플릭스 연결 시, 넷플릭스를 고정 지출로 추가하려 하면 "네이버플러스에 포함된 서비스예요" 경고). P2.

## 6. 카드 혜택

### 6.3 혜택 규칙 구조 [제안]

```
혜택(benefit)
├─ 대상: 가맹점 목록 | 업종 1개
├─ 종류: 할인 | 적립 | 캐시백
├─ 크기: 비율(%) | 정액(원)
├─ 1회 최대(원, 선택)
├─ 최소 결제 금액(원, 선택)
├─ 월 한도: 금액 | 횟수 | 없음
│   └─ 한도 묶음(선택): 여러 혜택이 한도를 함께 씀 ("통합 한도 1만원")
├─ 전월 실적 구간(선택): [{최소 실적, 크기 덮어쓰기, 월 한도 덮어쓰기}...]
├─ 요일·시간 조건(선택)
├─ 제외 조건(자유 텍스트 + 할부 제외·온라인 제외 체크)
└─ 출처: 직접 입력 | 붙여넣은 안내 문구
```

- 업종 목록(초안): 영화, 카페, 편의점, 대형마트, 온라인 쇼핑, 배달, 대중교통, 택시, 주유, 통신, 구독(OTT·음악), 외식, 병원·약국, 해외, 기타. 가맹점은 업종에 속한다(CGV → 영화).
- 가맹점 → 업종 연결표는 기본 사전(앱 내장) + 사용자 추가. 지출의 `내용`이 가맹점 이름과 일치하면 업종을 추정한다. [제안]

### 6.4 실적 계산 [제안]

```
카드 k의 기간 실적 = Σ (결제수단 = k 인 지출 금액)
                    − 환불
                    − 실적 제외 분류·업종에 해당하는 지출
                    (할부: 카드 설정에 따라 전액 또는 월 할부금)
이번 달 적용 구간 = 전월 실적이 넘은 가장 높은 구간
```

- 결제수단이 비어 있는 지출은 계산에서 빠진다. 해당 건수를 화면에 알린다(사용자가 판단할 수 있게). [확정 맥락]

### 6.5 "어떤 카드 쓸까" 추천 계산 [제안]

입력: 가맹점 또는 업종, 금액(선택), 날짜(기본 지금), 추가 조건(인원 수 등 — AI 질문으로 수집).

```
각 카드 k에 대해:
  1. 해당 대상(가맹점/업종)에 맞는 혜택 목록
  2. 이번 달 적용 구간 기준으로 혜택 크기·한도 확정
  3. 조건 검사: 최소 결제 금액, 요일·시간, 1회 최대
  4. 남은 월 한도(금액·횟수) = 한도 − 이번 달 이미 받은 혜택(예상 계산치)
  5. 예상 혜택 = min(금액 × 비율 또는 정액, 1회 최대, 남은 한도)
  6. 실적 영향: 이 결제로 이번 달 실적 구간이 올라가는지
정렬: 예상 혜택 내림차순 → 동점이면 실적 부족 카드 우선
```

- "이번 달 이미 받은 혜택"은 실제 카드사 데이터가 없으므로 **기록된 지출에 혜택 규칙을 적용한 추정치**다. 화면에 "기록된 지출로 계산한 예상값이에요" ⓘ. [확정 맥락: 입력 정도에 따라 정확도가 다름]
- AI 비서는 이 계산 기능을 도구로 호출하고, 부족한 입력(금액, 인원 수, 온라인/오프라인)을 선택지 질문으로 채운다. → [12 §5](12-ai-assistant.md)
- AI가 연결되지 않아도 이 화면만으로 추천이 동작한다.

### 6.6 AI 붙여넣기 구조화 [제안] P1

1. 사용자가 카드사 혜택 안내 문구를 붙여넣는다(최대 20,000자).
2. 서버가 AI에게 "혜택 규칙 구조(§6.3)"를 출력 형식으로 지정해 요청(구조화 출력).
3. 결과를 화면에 혜택 카드로 표시. 확신이 낮은 필드는 "확인 필요".
4. 사용자가 고른 혜택만 저장. 카드 `최종 확인일`을 오늘로.
5. AI에 보내는 것은 붙여넣은 문구뿐이다. 감사 로그에 "카드 혜택 정리 요청" 기록.

### 6.7 페이 [확정] → D-074

- 페이(네이버페이·카카오페이…)는 결제수단(kind=pay) + 페이 설정(`pays`: 연결한 카드·계좌, 메모). 자산 > 결제 수단 > 페이.
- **지출의 결제수단 = 돈이 실제로 나간 곳**(연결 카드·계좌, 페이 머니는 페이 자신). 거친 페이는 `transactions.pay_id`에 따로.
  → 카드별 합계·계좌의 카드 사용액은 결제수단만 보므로 페이를 거쳐도 한 번만 잡힘. 결제수단 필터에서 페이를 고르면 그 페이로 쓴 지출이 모두 나옴.
- 입력 창: 페이 칩을 고르면 "어디서 나갔나요?"(페이 머니 + 연결한 카드·계좌)가 나오고, 그 페이로 마지막에 고른 곳이 기본값.
- 페이 머니 충전은 지출로 적지 않음(내 돈 옮기기 — 적으면 두 번 잡힘). 목록 표시: "네이버페이 · 신한카드", "네이버페이 머니".
- 범위 밖: 고정 지출의 페이 경로, 페이 머니 잔액.

## 7. 계좌 [확정] → D-074

- 계좌 = 결제수단(kind=account) + 계좌 설정(`accounts`). 자산 > 결제 수단 > 계좌.
- 공통: 이름, 은행·증권사, 계좌번호(선택), 메모. 종류마다 칸이 다름(종류를 바꾸면 안 쓰는 칸은 비움):

| 종류 | 칸 | 보여 주는 계산 |
|---|---|---|
| 입출금 | 잔액 | |
| 예금 | 예치 금액, 연 이율, 시작일, 만기일, 이자 과세(일반 15.4%·세금우대 9.5%·비과세) | 예상 이자(단리) = 원금 × 이율 × 개월/12, 세후·만기 수령액, D-day |
| 적금 | 월 납입액 + 예금과 같은 칸 | 예상 이자(단리) = 월 납입액 × 이율/12 × n(n+1)/2 |
| 주식 | 투자 원금, 평가 금액 | 수익·수익률 |

- 모든 계좌: **연결된 카드**(카드 설정의 결제 계좌, 카드마다 이번 달 쓴 돈)와 **자동 결제**(이 계좌에서 바로, 또는 연결 카드로 나가는 해지 안 된 고정 지출).
- 계산은 `src/lib/accounts.ts`(확인: `scripts/check-accounts.mts`). 은행마다 다른 일수 계산·복리는 반영하지 않음.
- 지출 기록과 계좌 잔액을 자동으로 맞추지 않는다(직접 입력 원칙). 잔액 추이(스냅샷)·순자산·보유 종목은 나중에.

## 8. 가져오기 [제안] P2

- 카드사 이용내역 CSV·엑셀 업로드 → 열 매핑(날짜·내용·금액·결제수단) → 미리보기 → 중복 감지(날짜·금액·내용 같으면 "이미 있는 지출일 수 있어요") → 분류 자동 제안(과거 기록 기반) → 가져오기.
- 마이데이터가 아니라 사용자가 직접 내려받은 파일을 올리는 방식.
