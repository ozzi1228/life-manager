# 09. 위시리스트

> 문서 상태: 초안 v0.1 · 작성일 2026-11-01

## 1. 사용자 요구 [확정]

- 위시리스트 관리: 보고 싶은 영화·드라마, 읽고 싶은 책, 쇼핑 리스트.
- 쇼핑 리스트는 그냥 갖고 싶은 것과 정말 필요해서 사야 하는 것을 구별. **Want와 Like와 Need의 차이를 구별해야 함.**
- 보통 인스타 릴스나 광고 링크를 보고 위시리스트에 넣으므로, 무엇을 보고 넣었는지 알 수 있도록 항목마다 링크·이미지·텍스트를 입력.
- (추가 요구) 물건 목록에는 **가격**이 있어야 하고, 구매한 뒤 **구매했다고 체크**할 수 있어야 한다.
- (추가 요구) 갖고 싶음·관심 물건 중 한 달 내내 사지 않은 것은 **참은 소비** 목록에 들어간다. → [20 참은 소비](20-restraint-spending.md)
- (추가 요구) 영화·드라마·도서 위시는 **시청 완료·완독 처리 후 후기를 남기는 곳으로 넘어갈 수** 있어야 한다.

## 2. 위시 종류

| 종류 | 하위 | 다음 단계 |
|---|---|---|
| 작품 | 책 / 영화 / 드라마 | 읽기 시작·보기 시작 → 작품 기록 [08](08-journal-and-media.md) |
| 쇼핑 | (구분: 관심·갖고 싶음·필요) | 구매함 → 지출 [06](06-finance.md) |

## 3. 쇼핑 구분 [확정: Like·Want·Need 3구분, 화면 라벨 D-045] [제안: 정의 문구]

| 내부 | 화면 라벨 | 정의(i 팝오버 문구) | 정렬 순서 |
|---|---|---|---|
| `need` | 필요 | 생활이나 일에 꼭 필요해서 사야 해요. | 1 |
| `want` | 갖고 싶음 | 사고 싶지만 없어도 생활에 지장은 없어요. | 2 |
| `like` | 관심 | 눈여겨보는 중이에요. 당장 살 생각은 없어요. | 3 |

- 라벨 선정 이유: "Want/Like/Need"는 영어이고 Want와 Like의 차이가 한국어 사용자에게 직관적이지 않다. 행동 기준(필요 → 살 것 / 갖고 싶음 → 고민 중 / 관심 → 지켜봄)이 드러나는 단어로 바꾼다. 판단 기준은 i에만 둔다. [03 §7.1 원칙 1]
- 라벨은 `필요 / 갖고 싶음 / 관심`으로 확정했다(D-045). 검토했던 대안 `필요 / 사고 싶음 / 찜`은 쓰지 않는다.
- 구분은 언제든 바꿀 수 있고, 바꾼 이력이 남는다("관심 → 갖고 싶음, 11월 2일"). 이 이력은 상세 하단에 작게 보여 준다(충동구매 점검에 도움). [제안]

## 5. 링크 미리보기 [제안] [검증 필요]

- 링크를 붙여넣으면 서버가 해당 페이지의 공개 메타 정보(Open Graph: 제목, 대표 이미지, 가격 태그가 있으면 가격)를 가져온다.
- 서버 측 가져오기 안전 규칙: 사내망·로컬 주소 차단(SSRF 방지), 5초 제한, 2MB 제한, 이미지만 저장.
- 인스타그램·일부 쇼핑몰은 로그인 벽·봇 차단으로 실패할 수 있다 → 실패는 오류가 아닌 안내("직접 넣어 주세요"). 우회하지 않는다.
- 미리보기 이미지는 사용자 저장소에 복사해 보관할지 [미결정 Q-091] (추천: 복사 — 원본 게시물이 사라져도 "무엇을 보고 담았는지" 남기는 것이 핵심 목적).

## 6. 상태 흐름

```
담아둠 ──구매함──▶ 구매함 (지출 연결 또는 지출 없이)
   │                  └──되돌리기──▶ 담아둠 (연결 지출은 묻고 처리: 지출도 휴지통으로 / 지출은 남기기)
   └──그만둠──▶ 그만둠 ──다시 담기──▶ 담아둠
```

- 구매 처리 시 지출 입력 폼이 미리 채워진 채 열린다: 금액 = 가격, 내용 = 이름, 분류 = 쇼핑(설정 가능), 날짜 = 오늘. [04 §7.8]
- **구매 체크는 목록에서 바로** 할 수 있다: 카드(모바일 행)마다 원형 체크 버튼 `구매했어요`. 누르면 위 구매 처리 흐름이 열린다. 상세에 들어가지 않아도 된다. [확정: 구매 체크] [제안: 위치]
- `그만둠` 처리 시 "참은 소비로 기록할까요?" 선택(기본 켬, 가격만큼 그달 참은 금액에 더함). [20 §4.1]
- 참은 소비로 기록된 위시를 나중에 `구매함`으로 바꾸면 그 금액이 구매한 달의 참아야 할 금액에 더해진다. 구매 처리 화면에 미리 안내. [20 §5.3]

## 7. 작품 위시

| 필드 | 비고 |
|---|---|
| 종류 | 책/영화/드라마 |
| 제목·이미지 | 검색(작품 정보 검색과 같은 기능) 또는 직접 |
| 메모 | 누가 추천했는지 등 |
| 링크 | 선택 |

- 작품 위시 카드의 두 가지 버튼 [확정: 완료 처리 후 후기로] [제안: 버튼 구성]:

| 버튼 | 책 | 영화 | 드라마 | 열리는 화면 |
|---|---|---|---|---|
| 시작 | `읽기 시작` | — | `보기 시작` | 작품 기록 폼: 상태 읽는 중/보는 중, 시작일 오늘 |
| 완료 | `다 읽었어요` | `봤어요` | `다 봤어요` | 작품 기록 폼: 상태 완독/봤어요/다 봄, 끝난 날 오늘, **감상 입력란에 바로 포커스**(별점·한 줄 평·감상) |

- 완료 처리 흐름: 버튼 → 작품 기록 폼(제목·이미지·메모가 위시에서 채워짐) → 감상 작성 → `기록 저장` → 위시는 "다 봄" 묶음으로 이동하고, 작품 기록·포스터 캘린더에 그 날짜로 들어간다. 토스트 "작품 기록으로 옮겼어요 · 감상 보기".
- 감상을 비워 두고 저장해도 된다. 작품 기록 상세에 "감상을 남겨 보세요" 빈 상태가 보인다.
- 시작 버튼으로 옮긴 작품은 위시에서 "시작함" 묶음으로 가고, 이후 완료 처리는 작품 기록 화면에서 한다.

## 8. 화면 규칙 요약

- 쇼핑은 이미지 중심 카드 격자(무엇을 보고 담았는지 이미지로 기억). 이미지 없으면 링크 도메인 아이콘 + 이름.
- 오래 담아둔 `갖고 싶음` 항목을 홈 위젯에 보여 주는 옵션: "30일째 고민 중인 가죽 가방" — 사기·그만두기를 결정하도록 돕는다. [제안] P1
- 구분 필터 옆 ⓘ 하나로 정의 설명.

## 9. 다른 앱에서 바로 담기 [제안] P2 [검증 필요]

- 안드로이드: PWA Web Share Target으로 공유 메뉴에 앱 표시 → 링크·이미지를 받아 위시 담기 폼.
- iOS: Web Share Target 미지원 가능성 → 단축어(Shortcuts) 안내 또는 링크 복사 후 앱에서 `붙여넣기` 버튼(클립보드 읽기는 사용자 동작 필요).

## 10. 예외

| 상황 | 처리 |
|---|---|
| 같은 링크를 다시 담음 | "이미 담은 항목이에요" + `보러 가기` / `그래도 담기` |
| 가격 변동 | 추적하지 않음(범위 밖). 메모로 |

| 이미지 업로드 실패 | 썸네일 오류 표시 + 다시 시도 |
